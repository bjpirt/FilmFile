# FF-104 Mark frames to scan

**Status:** to do · **Group:** 1. Multi-version frames, finished off · **Was:** U22a

## Why

While looking through a roll, I can keep a durable selection of frames I intend to scan at higher resolution and distinguish work still pending from frames already scanned.

## What

Add a persistent `toScan` mark to each frame. Set or clear it from the frame view or in bulk. Show the pending mark on thumbnails, and show a related “Scanned” mark when a Raw scan or Final exists. A Raw scan or Final does not erase the selection; the roll count and future scan list count only marked frames that still need a Raw scan or Final. *(Split from U22.)*

## Acceptance criteria

- [ ] A frame with no `toScan` field in `roll.json` reads as `false`; a saved frame stores `toScan: true` only when marked. The frame API always returns a boolean `toScan` and accepts an optional boolean in single and bulk updates.
- [ ] In the frame view, the control reads “Mark to scan” when clear and “Marked to scan” when set; activating it toggles the mark. A numbered or unnumbered frame can be marked.
- [ ] In bulk edit, Set ▸ “Mark to scan” marks every selected frame, and Set ▸ “Unmark” clears every selected frame, in one versioned roll save. Success reads “2 frames marked to scan.” or “Scan mark removed from 2 frames.”, with singular grammar for one frame.
- [ ] A pending marked frame shows a scanner icon in the thumbnail mark row (U69, U70), named “To scan at higher resolution” for screen readers and on hover.
- [ ] A marked frame that has at least one Raw scan or Final shows a related scanner icon with a check, named “Scanned”. The mark remains set; adding a Raw scan or Final does not clear it.
- [ ] The roll heading appends the pending count to its frame count, e.g. “6 frames (2 to scan)”. It counts marked frames without a Raw scan or Final, uses “1 to scan” for one, and has no to-scan suffix when none are pending.
- [ ] Deleting the last Raw scan and Final from a marked frame keeps the mark and returns it to the pending “To scan at higher resolution” state.
- [ ] Renumbering a frame does not change its mark; its status remains attached to the frame ID.
- [ ] A save refused because the roll changed (409) leaves the mark unchanged and uses the existing message: “This roll changed since you opened it. Reload the page.”
- [ ] The later FF-131 scan list includes marked frames only while they have no Raw scan or Final; already-scanned marked frames are omitted.
- [ ] The “Bulk edit” journey covers setting and clearing marks and seeing the thumbnail states; the existing Raw scan upload behavior continues to pass.

- `toScan` is frame state, not inherited metadata. Missing persisted values default to false; no schema bump or migration is needed.
