# FF-171 A date for a new event added from a roll

**Status:** done · **Built in:** 4. Metadata

## Why

An event added on the spot while creating or editing a roll should get its date then, not need a trip to the Events page.

## What

"New event" under a roll's Event field (on New roll and in Edit details) has an optional "Event date" (a year, then optionally a month and day) beside its name, sent when the event is made.

## Acceptance criteria

- [x] Choosing "Add new…" for a roll's Event shows "Event date" (Year, Month, Day), empty at first, under the new event's name, on New roll and in Edit details.
- [x] The event is made with the date given, as precisely as it's given (`2025`, `2025-06` or `2025-06-14`), and with none when it's left empty.
- [x] A year that isn't four digits says "Enter the event’s year as four digits, like 2026." and nothing is created, event or roll.
- [x] A day that isn't on the calendar, which the service refuses, says "The event's date doesn't exist. Check the day and month." and nothing is created.
- [x] The date doesn't change what happens when the archive already has the event (it's used, as before).

## Not in this task

- Changing an existing event's date from the roll's form (the event's own page and the Events page do that).

## What was built

`NewEvent` (`events/event-choice.ts`) holds a `date` (`ShotFields`) beside the name; `events/event-field.tsx` shows the same `DateShotFields` the Events page's form uses, as "Event date", on its own row inside the "New event" box; `events/choose-event.ts` checks the year, sends the date with the new event, and tells a refused date from a refused name. The web tests' fake service refuses a date that isn't on the calendar, as the service does. Page tests cover New roll (a full date, none, a bad year, a day that doesn't exist) and Edit details.
