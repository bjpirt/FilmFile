# FF-194 The app's version

**Status:** done · **Built in:** 10. Desktop app

## Why

Knowing which FilmFile I'm running, so I can tell whether a release has what I need and say which one has a problem, and never mistake a build from source for a release. And a way from the app to where FilmFile lives, to read about releases or report a problem.

## What

FilmFile gets a real version number, kept only in the root `package.json` and starting at `0.1.0`. It's shown at the foot of Settings, in the app and in a browser, and in the app's "About FilmFile", a box of our own on every platform with a button to FilmFile on GitHub. A Help menu, on every platform, also has "FilmFile on GitHub". Run from source, the version is marked "(dev)". The API gives it on `GET /api/health`, and the disk image `pnpm package` makes carries it in its name. The Release workflow (FF-195) is what changes it.

## Acceptance criteria

- [x] The root `package.json` is at version `0.1.0`. No other `package.json` holds FilmFile's version (`apps/desktop`, `apps/backend`, `apps/web` and `packages/contracts` stay at `0.0.0`).
- [x] `GET /api/health` gives `version` ("0.1.0") and `dev` (`true` from source, `false` in a packaged app), and both are in the OpenAPI spec.
- [x] At the foot of Settings, below everything else, a quiet line reads "FilmFile 0.1.0", in the app and in a browser. Run from source (`pnpm start`, `pnpm dev`, `pnpm desktop`), it reads "FilmFile 0.1.0 (dev)".
- [x] Until health answers, or if it fails, the line isn't shown; the rest of Settings is unchanged.
- [x] A packaged app, from `pnpm package` or a release, shows the version it was built with, unmarked, however the service inside it is started.
- [x] On a Mac, the app menu ("FilmFile") has "About FilmFile" first, then the standard items (Services, Hide FilmFile, Hide Others, Show All, Quit FilmFile).
- [x] On Windows and Linux, a Help menu has "FilmFile on GitHub", a separator, then "About FilmFile".
- [x] On a Mac, a Help menu has "FilmFile on GitHub".
- [x] "About FilmFile" opens the same message box on every platform, titled "About FilmFile" (a Mac doesn't show a message box's title), with the app's icon as each platform shows it, "FilmFile" and "Version 0.1.0" ("Version 0.1.0 (dev)" from source), with the buttons "FilmFile on GitHub" and "OK" ("OK" the default, and what Escape does).
- [x] "FilmFile on GitHub", in the Help menu or the About box, opens `https://github.com/bjpirt/FilmFile` in the default browser. From the box, the box closes.
- [x] `pnpm package` names its disk image `FilmFile-0.1.0-mac-arm64.dmg`. The app folder keeps the packager's name (`FilmFile-darwin-arm64/`), so `install-app` and the packaged-app journey don't change. CI uploads the new name.

## What was built

- `GET /api/health` gives `{ status, exportToFolder, version, dev }`. The service reads its version in `apps/backend/src/composition/app-version.ts`; the desktop app reads its own the same way in `apps/desktop/src/app-version.ts` (it imports nothing of the service's, D54). From source each reads the root `package.json`; `package.ts` defines `FILMFILE_VERSION` in both bundles with rolldown's `transform.define`, which makes them report it with `dev: false`.
- Settings ends with a muted line, "FilmFile 0.1.0 (dev)" or "FilmFile 0.1.0", from the `['health']` query, now shared through `apps/web/src/health/health-query.ts` with the export-to-folder check. Nothing is shown until health answers, or if it fails.
- `apps/desktop/src/app-menu.ts` now returns the menu's template, unit-tested for each platform: on a Mac an app menu built by hand (About FilmFile, Services, Hide FilmFile, Hide Others, Show All, Quit FilmFile) and Help with "FilmFile on GitHub"; elsewhere Help with "FilmFile on GitHub", a separator and "About FilmFile". `about-box.ts` gives the box's text and buttons; `main.ts` shows it with `dialog.showMessageBox` and opens GitHub with `shell.openExternal`.
- `pnpm package` writes `out/FilmFile-<version>-mac-<arch>.dmg`; CI uploads `out/FilmFile-*.dmg`. The Windows and Linux menus are unit-tested only, until those apps are built (FF-197, FF-198).

## Not in this task

- Changing the version, the changelog and releases (FF-195). The first release is `0.1.0` as this task sets it.
- Telling you a newer version is out (FF-138), or a "What's new" link.
- The commit a build was made from.
- A credits or copyright line in About, and a link from Settings' version line.
- The Intel Mac's disk image (FF-161), and the Windows and Linux apps' file names (FF-197, FF-198).

## Notes

- One source: the root `package.json` (D109). The service reads it when run from source. When `package.ts` bundles the service, rolldown replaces a constant with the version, so the packaged service knows it however it's started. `package.ts` also writes it into the app's `package.json` and the disk image's name. `dev` is `true` only when the version came from reading `package.json` at run time; there's no environment variable for it.
- One About box everywhere, Electron's `dialog.showMessageBox`, not the Mac's native About panel, which can't hold a link (D124). The Mac's app menu is built by hand in place of the `appMenu` role, so its About opens our box. The desktop app learns the version from health, like the UI, or reads it the same way the service does; the box's text and buttons are worked out by a plain function. The link opens with `shell.openExternal`.
- Health: `{ status: 'ok', exportToFolder, version: string, dev: boolean }`. Run `pnpm generate`. The web reads it with the `['health']` query `use-export-to-folder.ts` already makes.
- Tests:
  - Unit: reading the version; the About box's contents (with and without "(dev)"); the menus' items on a Mac and elsewhere.
  - API: health's `version` and `dev`.
  - Web: Settings shows "FilmFile 0.1.0 (dev)" from a fake health, and no line when health fails.
  - Packaged-app journey: health gives the version the app was built with, and `dev` is `false`.
  - `desktop.e2e.ts`: the menu has "About FilmFile" and "FilmFile on GitHub" (by id).
  - The message box and the browser aren't opened in tests.
