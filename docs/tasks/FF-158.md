# FF-158 Require a shot year when creating a roll

**Status:** to do · **Group:** 2. Roll numbers

## Why

Numbering rolls by shot date needs every new roll to have a shot year. The New
roll page already requires one, but the API currently accepts a roll without
a date and falls back to the current year for its number.

## What

Require a valid shot date with at least a year when creating a roll through
the API, matching the New roll page. A request without `shot` is refused
instead of creating an undated roll numbered for the current year.

## Acceptance criteria

- [ ] `POST /api/rolls` without `shot` returns 422 with an issue on `shot` and
      creates no roll.
- [ ] A valid shot date with at least a year creates the roll as before; an
      automatically assigned number uses that shot year.
- [ ] The generated API contract marks `shot` as required, and the service no
      longer uses the clock's year as a fallback for a roll created without a
      shot date.

## Not in this task

- Adding or changing the shot date of an existing roll.
- Migrating existing archive records; FF-108 assumes its rolls have shot
  dates.

## Notes

- Needs FF-152's automatic roll numbering. Replaces the no-shot-date API
  fallback in D67 and is a prerequisite to FF-108.
- API: `POST /api/rolls`; update the request contract, `CreateRoll`, and the
  OpenAPI-generated client and spec.
- Tests: API and use-case tests for a missing shot date, plus the generated
  contract check. The New roll page already requires the year.
