# FF-191 Rebuild a site from scratch

**Status:** done · **Group:** 13. Sites · **Built in:** 13. Sites

## Why

To start a site afresh when I don't trust what's there (an image looks wrong, files were changed by hand, or something went wrong part-way), without having to delete the site's folder myself.

## What

Beside "Build site" on a site's page, "Rebuild from scratch" builds the site again making every image and page anew, even when it's up to date, instead of keeping the images it already has. _(Asked for while reviewing FF-189.)_

## Acceptance criteria

- [x] A site's page has "Rebuild from scratch" next to "Build site", shown once the site has been built, disabled while a build or a save is going on.
- [x] It builds the site with every image made again: the message says "(N images made, 0 unchanged)" even when the site was up to date.
- [x] The result is the same site a first build makes: images left over from earlier builds are gone, and anything else in the folder is replaced as a build replaces it (the swap is still whole, so a failed rebuild leaves the site as it was, D92).
- [x] Afterwards the site reads "Up to date".
- [x] A site with no frames asks "This site has no frames. Build it anyway?" first, as "Build site" does.

## What was built

- `BuildSite` takes `fresh`: it builds even when up to date and brings no image across; `SiteBuilds.start` passes it on; the build route takes `?fresh=true` (`siteBuildQuery` in the contracts; anything else is refused with 422).
- The build panel (`build-panel.tsx`) shows "Rebuild from scratch" once the site is built, disabled while a change is saved and hidden while a build runs; an empty site asks first, with "Rebuild from scratch" as the answer.
- Tests: the use case (every image made, none kept, up to date afterwards), the API (`fresh=true`, `fresh=yes` refused), the web (offered once built, waits for a save, the empty-site question) and `build-site.e2e.ts` (rebuild from scratch: every image made, 0 unchanged).

## Not in this task

- Deleting a built site, or emptying `Sites/`.
- Rebuilding every site at once.

## Notes

- API: `POST /api/sites/{slug}/build?fresh=true` (now `?rebuild=all`, since FF-193 added `?rebuild=pages`); with it the build keeps no image from the built site. _(Planned as a request body; the build request has none, so a query is the smaller change.)_ OpenAPI regenerated.
- Settled when built: "Rebuild from scratch", beside "Build site", with no confirmation (it changes nothing but the built site, which a cancel or failure leaves as it was).
- Tests: the use case (fresh build makes every image, leaves no old one), the API (`fresh`), the web (button, disabled states, confirmation for an empty site) and `build-site.e2e.ts` (rebuild from scratch, every image made).
