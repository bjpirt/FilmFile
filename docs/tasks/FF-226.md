# FF-226 Sync status in the header

**Status:** done · **Built in:** 17. Sync and backup

## Why

Seeing at a glance whether the library is backed up, and syncing from any page, without opening Settings.

## What

Once sync is set up in the desktop app, the right end of the header shows how the backup stands, with a cloud icon, and opens a panel with "Sync", its progress and "Cancel", and a link to the Sync settings. Settings keeps its own "Sync", from the same component. Edits stay open while a sync uploads (D121).

## Acceptance criteria

- [x] Without the desktop app, or until a Cloudflare account ID and a bucket are set, the header shows nothing new.
- [x] Once they are, the header's right end, after Settings, shows a cloud icon and "Not synced yet", or "Synced just now", "Synced 5 min ago", "Synced 2 h ago", "Synced 3 days ago", and after a week the date ("Synced 9 Nov"). The full time ("16 Nov 2026, 14:02", in this computer's time zone) shows on hover, and the words update every minute.
- [x] While a sync runs, the header reads "Syncing 34%" (by size), and moves on to "Synced just now" when it finishes. A sync started in Settings shows there too, and the other way round.
- [x] On a phone, the header shows only the icon, with the words as its accessible name.
- [x] Clicking it opens a panel under it. Escape or a click outside closes it, and focus goes back to the button. The panel has the last sync's full time ("Synced 16 Nov 2026, 14:02"), what it sent ("Sent 12 files (1.2 GB)." or "Nothing had changed."), "Sync" and "Sync settings", which goes to Settings. While syncing, it has the progress and "Cancel", as in Settings.
- [x] A sync that failed shows in the header as "Sync didn't finish", with a warning mark. The panel says why, in Settings' words (with "Open Settings" where that's the fix), and "Sync" tries again.
- [x] A cancelled sync leaves the header on the last finished sync ("Synced 2 h ago"). The panel says "Sync didn't finish. Nothing already backed up was lost. Try again."
- [x] How the last sync went is kept only while the service runs. After a restart, the header shows the last finished sync.
- [x] `GET /api/sync` also says whether sync is ready (the account ID and the bucket set), and it's in the OpenAPI spec.

## What was built

- **API:** `GET /api/sync` gained `ready` (in the desktop app, with the account ID and a bucket set), worked out by `LibrarySync.status(ctx)`.
- **Page** (`apps/web/src/sync/`): `SyncStatusButton` at the right end of the header (`app.tsx`), with a cloud icon, `aria-label` the words and `title` the full time, opening a `role="dialog"` panel named "Sync"; `SyncControls`, the "Sync", progress, "Cancel" and failure messages moved out of `settings/sync-section.tsx` and shared by Settings and the panel; `useSyncStatus`, one query (`['sync']`) for both, polled every 400 ms while a sync runs; and `syncedAgo`, the short relative time. Saving the account ID or the bucket in Settings refreshes the status, so the header appears at once. Below 40rem only the icon shows.
- **Tests:** API (`ready` in each case), web (`synced-ago.test.ts`, and `sync-status-button.test.tsx` for each header state, the panel, Escape and clicking elsewhere, and a sync started in Settings showing in the header), and the backup journey (`test/e2e/back-up.e2e.ts`) syncing from the header panel.

## Not in this task

- Edits waiting while a sync runs: the 423 and the read-only page come with syncing down (FF-228), which needs them, shared with the lock (FF-229) (D121).
- Which computer synced last, and the out-of-date warning (FF-228). Who is editing (FF-229).

## Notes

- **Decisions:** D115, D120, and D121 (edits stay open during an upload).
- **API:** `GET /api/sync` gains `ready`. Like `GET /api/sync/settings`, it says whether the account ID and the bucket are set. The header reads only this route, polling every 400 ms while a sync runs, as Settings does, under the same query key so the two agree.
- **Page:** the header's status is a button (with `aria-expanded`) opening a panel, like the existing menus. The panel's "Sync", progress, "Cancel" and failure messages move out of `settings/sync-section.tsx` into one component used by both. Relative time is a small function of our own (`syncedAgo(iso, now)`), table-tested, not a dependency.
- **Tests:** unit (`syncedAgo`'s thresholds), API (`ready`), web (each header state: hidden, not synced yet, synced ago, syncing with a percentage, didn't finish, cancelled; the panel opening, closing on Escape and syncing; the phone's icon-only name), and the FF-225 journey (`test/e2e/back-up.e2e.ts`) extended to sync from the header panel and see "Synced just now".
