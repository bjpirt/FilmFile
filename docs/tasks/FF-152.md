# FF-152 New rolls numbered automatically

**Status:** to do · **Group:** 2. Roll numbers

## Why

Importing a pile of rolls shouldn't stop at working out each one's number first: they get one straight away and are put in order later (FF-108).

## What

New roll opens with the next free roll number filled in, from the year shot or this year's, and the service gives a roll created with no number the next free one too, both changeable afterwards (D67). The page works its suggestion out from the rolls it already has; the service keeps its own copy of the same rule. *(Replaces D8, under which the service never invented a number.)*

## Acceptance criteria

The page:

- [ ] New roll opens with "Roll number" filled with the next free number for this year, e.g. `2026-015` when `2026-014` is the highest, and the Year filled to match (D27: the Year follows the number).
- [ ] Changing the Year by hand to another four-digit year changes the number to that year's next free one (`2025-004`), as long as the number hasn't been typed over; a half-typed year leaves it as it was.
- [ ] A number typed by hand is kept, whatever the Year then becomes, and checked as now (`YYYY-NNN`, not taken).
- [ ] Typing a number still fills the Year, until the Year has been changed by hand.
- [ ] Emptying the Roll number and saving asks for one, as now: "Enter a roll number like 2026-014."
- [ ] The suggestion is the highest number of that year plus one (`2026-001` for a year with none), so gaps left by deleted rolls aren't reused, and a number an unreadable roll's folder is named for counts as taken.
- [ ] A number typed before the suggestion arrives isn't replaced by it.
- [ ] A number that's taken when it's saved (another tab made it) says "Roll 2026-015 already exists." as now.

The API:

- [ ] `POST /api/rolls` takes a roll with no `roll` and gives it the next free number for its date shot's year, or this year's by the service's clock when it has no date; the created roll says which.
- [ ] The next free number is the same rule as the page's: the highest of that year plus one, counting unreadable rolls' folders.
- [ ] Two rolls created with no number at once never get the same number: when one is taken in between, the service picks again.
- [ ] A year that has 999 rolls has no number left: a roll created with no number then is refused as a problem with `roll` ("no roll numbers are left for 2026"), and one created with a number is checked as now.
- [ ] A roll sent with a number is created with it, as now: nothing changes for callers that give one.

## Not in this task

- Numbering many rolls in date order (FF-108).
- Patterns other than `YYYY-NNN` (FF-153).
- Importing many rolls at once (FF-154).
- A service route for the suggestion: the page works it out itself.

## Notes

- Decision D67. A number given automatically is provisional like any other until the roll is filed (FF-107).
- The rule is written twice, as a pure function in each of the service (`nextRollNumber`, `domain/rolls/`) and the page, over the same inputs (the rolls' numbers and the unreadable folders' names), so the two must agree; both are tested with the same cases.
- API: `POST /api/rolls` with `roll` optional; the use case, `CreateRoll`, takes the year from the date shot or the `Clock` port (this year), and on a taken number from a race tries again a few times before giving up.
- Tests: domain tests for the rule (empty year, gaps, 999, unreadable folders), use case tests (numberless create, the year from the date shot, this year's, a race), API tests, and page tests for the suggestion, changing the Year, typing over it and the empty field. No journey: the journeys share an archive, so the next number depends on what they made; the existing ones type their own numbers over the suggestion.
