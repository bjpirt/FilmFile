# FF-226 Sync status in the header

**Status:** to do · **Group:** 17. Sync and backup

## Why

Seeing at a glance whether the library is backed up, and syncing from anywhere, without opening Settings.

## What

Once sync is set up, the header shows how things stand and opens a sync panel with the "Sync" button and its progress. While a sync runs the person can keep browsing, but edits wait until it finishes.

## Acceptance criteria

- [ ] With sync not set up, the header shows nothing new.
- [ ] With sync set up, the header reads "Not synced yet", "Synced 2 h ago" (relative time, the full time on hover) or "Syncing…" while one runs.
- [ ] Clicking it opens the sync panel: the last sync's time and computer, "Sync" and, while syncing, progress and "Cancel". A link goes to the Sync settings.
- [ ] While a sync runs, pages can be browsed. Every control that changes the library is disabled, with "Waiting for sync to finish" on hover. The service refuses writes with 423 until it finishes.
- [ ] A failed sync shows in the header as "Sync didn't finish", and the panel says why, with "Try again".

## Not in this task

- The out-of-date warning (FF-228) and who is editing (FF-229).

## Notes

- Reads `GET /api/sync`. Polls while a sync runs, as builds do.
- Refusing writes during a sync is one check in the HTTP adapter's write routes, shared later with the lock (FF-229).
- **Tests:** API (a write during a sync is 423), web (each header state, the panel), and the FF-225 journey extended to sync from the header.
