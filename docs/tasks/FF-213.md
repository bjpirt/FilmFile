# FF-213 Split the roll page by mode

**Status:** to do · **Group:** 16. Internal improvements

## Why

`apps/web/src/rolls/roll-page.tsx` is 1,162 lines with 17 `useState` calls: fetching, saving, conflicts, selection, renumbering, uploading and drawing the page all live in one component. With its data code moved out (FF-212), what's left can be split so each part reads on its own.

## What

The roll page is split by what it's doing, each part in its own file beside it: choosing frames (select, give details, delete, export), renumbering, and the drop zone for scans with its progress. The two small components at the top of the file, `RollAbout` and `ProposedNumber`, move to their own files. The page component is left deciding which mode is showing and holding the state they share. Nothing a person sees changes. _(Recommendation R7 of the architecture review, the roll page's split; after FF-212.)_

## Acceptance criteria

- [ ] `RollAbout` and `ProposedNumber` are each in their own file in `apps/web/src/rolls/`, named after them (`roll-about.tsx`, `proposed-number.tsx`).
- [ ] Choosing frames is its own component in its own file: the selection bar, giving the chosen frames details, deleting them and exporting them, with the state only it uses (for example `selection`, `exportingSelected`).
- [ ] Renumbering is its own component in its own file, with the state only it uses (`renumbering`, `savingNumbers`, `numbersNotSaved`), beside the existing `renumber-panel.tsx`.
- [ ] Adding scans (the drop zone and the upload's progress) is its own component in its own file, with `upload` and `addingScans`.
- [ ] `roll-page.tsx` holds the roll, which mode is showing and the state the modes share (such as "changed elsewhere"), and is a few hundred lines.
- [ ] `roll-page.test.tsx`, the other web tests and the Playwright journeys pass unchanged.

## Not in this task

- New behaviour, wording or layout.
- Tests for each new component on its own: the page's tests cover them through what a person sees, which is the right level.
