# FF-191 Rebuild a site from scratch

**Status:** to do · **Group:** 13. Sites

## Why

To start a site afresh when I don't trust what's there (an image looks wrong, files were changed by hand, or something went wrong part-way), without having to delete the site's folder myself.

## What

Beside "Build site" on a site's page, "Rebuild from scratch" builds the site again making every image and page anew, even when it's up to date, instead of keeping the images it already has. _(Asked for while reviewing FF-189.)_

## Acceptance criteria

- [ ] A site's page has "Rebuild from scratch" next to "Build site", shown once the site has been built, disabled while a build or a save is going on.
- [ ] It builds the site with every image made again: the message says "(N images made, 0 unchanged)" even when the site was up to date.
- [ ] The result is the same site a first build makes: images left over from earlier builds are gone, and anything else in the folder is replaced as a build replaces it (the swap is still whole, so a failed rebuild leaves the site as it was, D92).
- [ ] Afterwards the site reads "Up to date".
- [ ] A site with no frames asks "This site has no frames. Build it anyway?" first, as "Build site" does.

## Not in this task

- Deleting a built site, or emptying `Sites/`.
- Rebuilding every site at once.

## Notes

- API: `POST /api/sites/{slug}/build` takes an optional `{ "fresh": true }`; with it the build keeps no image from the built site (`imagesToMake` is every wanted image). OpenAPI regenerated.
- To settle when refined: the button's name ("Rebuild from scratch", "Rebuild all"), whether it asks to confirm (a big site takes a while), and whether it goes in the site's Actions menu rather than beside "Build site".
- Tests: the use case (fresh build makes every image, leaves no old one), the API (`fresh`), the web (button, disabled states, confirmation for an empty site) and `build-site.e2e.ts` (rebuild from scratch, every image made).
