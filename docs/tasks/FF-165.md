# FF-165 Export a frame

**Status:** done · **Built in:** 12. Exports

## Why

Sometimes I just want one photograph as a file, once, to send to someone or print, without making and keeping an export for it.

## What

An "Export" button in the frame view opens the Export dialog (D97) for that frame, with a size and quality; the frame is made as a JPEG and downloaded the normal browser way. Nothing is saved but the choices last used. This builds the Export dialog, which every way of exporting uses (selected frames, FF-167; rules, FF-164; saved exports, FF-116), and the image rendering exports and sites share.

## Acceptance criteria

- [x] The frame view's bar has an "Export" button, beside the scan mark and rotate buttons, opening the dialog "Export frame 12A".
- [x] The dialog has a "Frames" line saying what's being exported ("This frame: 12A of roll 2026-014"), "Size" (Full size, or a longest edge in pixels, 2048 px at first) and "Quality" (1 to 100, 90 at first), and "Download" and "Cancel".
- [x] The last size and quality chosen are remembered in the browser and are what the dialog starts with.
- [x] "Download" downloads a JPEG named for the frame (`2026-014-12A.jpg`; `2026-014-frame.jpg` for a frame with no number), made from the frame's version shown (FF-103), turned as the frame view shows it, at the size and quality chosen.
- [x] A raw version shown is made from the largest preview it carries; a frame with no version says "This frame has no scan to export." in the dialog and makes nothing.
- [x] The file carries only the author and copyright (the archive's or the roll's) until FF-118 gives the choice; no location is ever written.
- [x] A failure before the download starts says what went wrong, without internals.

## Not in this task

- The Metadata choice (FF-118), exporting several frames (FF-167), rules as the frames (FF-164, FF-177), and saving the choices as an export (FF-116, FF-117).
- Choosing where the file is saved: that's the browser's (it asks, or saves to Downloads), or in the desktop app FF-166.

## Notes

- D95. API: `POST /api/exports/quick` with the frames (roll and frame IDs) and the recipe checks them and gives a single-use download address; `GET` on it streams the file with a `Content-Disposition` filename. The page follows the address as an ordinary download (no blob held in memory), and the service writes nothing to disk. FF-167 sends several frames the same way.
- The dialog is one component with a "Frames" source (a list of frames now; rules from FF-177) and the recipe's fields, whose output is "Download" (and, from FF-116, "Save as an export…"); the saved export's own page is the same component, expanded (D97).
- A hidden frame (FF-174, D99) can't be exported: it's unhidden first.
- The rendering (the version shown, turned as it's shown, resized, quality, metadata) is one piece of code in the service that FF-167, FF-117 and building a site (FF-120) all use.
- The remembered choices are a per-viewer convenience in the browser's storage, not a saved record.
- Tests: the rendering (size, quality, the turn, a raw's preview, the author and copyright written), the use case and API (a frame with no version, a bad request, the single-use address), the dialog, and a journey: open a frame, export it and find the JPEG.

## What was built

A new `ImageRenderer` port (sharp and in-memory adapters, with a contract suite; the raw-preview choice moved to `adapters/outbound/sharp/preview-source.ts` so thumbnails and exports share it) makes the JPEG: turned as shown, resized without enlarging, at the quality, carrying only EXIF Artist and Copyright. A new `ExportTickets` port (in-memory adapter, five-minute single-use tickets) backs `POST /api/exports/quick` (`PrepareQuickExport`: refuses a hidden frame or one with no scan) and `GET /api/exports/quick/{ticket}` (`MakeQuickExport`: from the version shown, with a `Content-Disposition` name from `exportFileName`). In the browser, `exports/export-dialog.tsx` is the dialog (Frames line, Size as Full size, 1024, 2048 or 4096 px, Quality, Download, Cancel) and `exports/export-choices.ts` remembers the last choices; the frame view has an "Export" button. Tests: both ports' contract suites, the renderer, the API, the dialog in the frame view, and the `export-frame` journey.
