# FF-193 Rebuild a site's pages only

**Status:** done · **Group:** 13. Sites · **Built in:** 13. Sites

## Why

To refresh a built site's pages (after a change to how sites look, or files touched by hand) without waiting for every image to be made again.

## What

Beside "Rebuild from scratch" on a site's page, "Rebuild pages only" builds the site again even when it's up to date, writing every page, the stylesheet and the script anew while keeping the images it has. _(Asked for after FF-191.)_

## Acceptance criteria

- [x] A built site's page has "Rebuild pages only" after "Rebuild from scratch", shown and disabled as that is (once built; not while a change is saved; hidden while a build runs).
- [x] It builds the site again even when it's up to date: every page and asset is written anew, and every image kept, so the message says "(0 images made, N unchanged)". Images whose inputs changed are still made, as any build makes them.
- [x] A site with no frames asks first, as the other buttons do; afterwards it reads "Up to date".

## What was built

- `BuildSite`'s `fresh` became `rebuild`: `all` (FF-191) or `pages`, which builds when up to date but keeps the images. The build route's `?fresh=true` became `?rebuild=all` or `?rebuild=pages` (`siteBuildQuery`); anything else is refused with 422.
- The build panel shows "Rebuild pages only" beside "Rebuild from scratch".
- Tests: the use case (pages rewritten, images kept), the API (`rebuild=pages` rewrites a page changed by hand, `rebuild=yes` refused), the web (the button, its request) and `build-site.e2e.ts` (0 images made).

## Not in this task

- Rebuilding only one page, or only the images.
