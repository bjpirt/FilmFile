# FF-101 One event per frame

**Status:** to do · **Group:** 1. Multi-version frames, finished off · **Was:** U72

## Why

A frame was only ever given one event in the browser, and grouping a roll by event (FF-102) needs each frame under one heading.

## What

A frame's own event becomes one event, like its roll's (D50), in roll.json, the API and the web app. Nothing changes in what a person sees.

## Acceptance criteria

- [ ] roll.json keeps a frame's own event as `event`, a slug, present only when the frame has one of its own.
- [ ] `PATCH …/frames/{frameId}` and `PATCH …/frames` take `event`: a slug, or null to go back to the roll's.
- [ ] A roll.json whose frames have `events` lists is read with each frame's first event, and saved with `event` the next time the roll is saved.
- [ ] The frame view, bulk edit's Set ▸ Event… and an event's page work as before.
- [ ] The "Bulk edit" journey still passes.

## Not in this task

- Sub-events (FF-130).

## Notes

- D50 replaces D25's "a frame can be in several".
- A frame's `events` with more than one, only possible by hand or through the API, keeps only its first.
