# FF-105 The FilmFile folder

**Status:** to do · **Group:** 2. The FilmFile folder · **Was:** U89

## Why

One place to find, back up and move, with the library kept apart from what's made from it.

## What

The desktop app asks for a FilmFile folder rather than the archive (replacing U83's question), and keeps everything in fixed folders inside it: `Library/` (the archive), `Exports/` (FF-117), `Sites/` (FF-120) and `Editors/` (the NegPy folder, FF-112). Replaces U73's NegPy folder setting.

## Acceptance criteria

- [ ] On first launch the app asks "Where should FilmFile keep its files?" with the system's folder picker, suggesting `~/Pictures/FilmFile`.
- [ ] Choosing an empty folder makes `Library/`, `Exports/`, `Sites/` and `Editors/` in it, and opens on "Set up your archive" for the new library.
- [ ] Choosing a FilmFile folder that has a library opens it.
- [ ] Choosing a folder of other files is refused, as U83 refuses one.
- [ ] An archive chosen with U83 is still opened; its FilmFile folder is then the folder the archive is in, and the other folders are made there only when first needed.
- [ ] Settings shows where the library, exports, sites and editors folders are.
- [ ] The choice is remembered per computer (D52), and File › "Open FilmFile Folder…" switches, as "Open Archive…" does now.
- [ ] The service is told the FilmFile folder (`FILMFILE_FOLDER`); `FILMFILE_ARCHIVE` on its own still works, for development and the journeys.

## Not in this task

- Putting one of the folders somewhere else (on a NAS, say).

## Notes

- Caches stay in the OS cache folder, never in the FilmFile folder.
- Backup and sync (design section 10) cover `Library/` only.
- Journeys: extend the desktop app's first-launch journey.
