# FF-109 Originals read-only

**Status:** to do · **Group:** 2. Finding your way around the library · **Was:** U74

## Why

Links to originals (the browse folder, the NegPy folder) mustn't let another program write to them.

## What

The service makes each original read-only as it stores it, and makes a roll's originals read-only before linking them (FF-111, FF-112) if they aren't yet (D51).

## Acceptance criteria

- [ ] A file added as a version is read-only on disk once stored (no write permission for anyone).
- [ ] Originals stored before this are made read-only when they're first linked (FF-111, FF-112).
- [ ] Deleting a version or frame (moving it into `deleted/`) still works with read-only files.
- [ ] Rotating a frame, which never touches its files, still works.

## Not in this task

- Making existing originals read-only all at once (the integrity check could, FF-125).

## Notes

- Through the `BlobStore` port; its contract suite checks it.
