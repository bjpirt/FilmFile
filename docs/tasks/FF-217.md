# FF-217 Split the rolls route file

**Status:** to do · **Group:** 16. Internal improvements

## Why

`apps/backend/src/adapters/inbound/http/routes/rolls.ts` is 806 lines holding all 18 routes for rolls, frames and versions. A reader looking for one route has to scroll through the rest, and the small response helpers it defines are copied into five other route files.

## What

The rolls routes are split into three files by resource (rolls, a roll's frames, a frame's versions), each with its own use-case interface and route function, all mounted under `/api/rolls` as now. The shared response helpers move to one file the route files use. The type naming every use case the app needs is written once. The API doesn't change: the generated OpenAPI spec is identical. _(Recommendation R8 of the architecture review, step 1 and its last note; before FF-218.)_

## Acceptance criteria

- [ ] `routes/rolls.ts` holds list, numbering snapshot, renumber, get, create, update and delete a roll, with `RollUseCases` for those.
- [ ] `routes/roll-frames.ts` holds create, update one, update many, delete one, delete many and details of frames, with `RollFrameUseCases`.
- [ ] `routes/frame-versions.ts` holds add, update and delete a version, its original file and its thumbnail, with `FrameVersionUseCases`.
- [ ] All three are mounted at `/api/rolls` in `create-app.ts`; every address is as now.
- [ ] The response helpers (`json`, `image`, `versionImage`, `invalid`, `malformed`, `wrongType`, `requireJson`) are in one file beside the routes, and `events.ts`, `exports.ts`, `equipment.ts`, `sites.ts` and `settings.ts` use its `json` and `requireJson` instead of their own copies.
- [ ] `pnpm generate` produces an `openapi.json` identical to before (the check that nothing moved by accident), and the OpenAPI snapshot test passes unchanged.
- [ ] The intersection of every use-case interface is written once, exported from `create-app.ts` as `UseCases`, and used by `createApp`'s config and `useCasesFor`'s return type.
- [ ] Every API test passes unchanged.

## Not in this task

- The ID guards and the dropped frame IDs (FF-218).
- A helper for the `If-Match` check, repeated 8 times. Leave it unless one can keep Hono's typed responses without a type assertion; three lines repeated beat a helper that needs an `eslint-disable`.
- `routes/frames.ts` (the search for a selection's frames, at `/api/frames`): it stays as it is. The new frames file is named `roll-frames.ts` so the two don't clash.
