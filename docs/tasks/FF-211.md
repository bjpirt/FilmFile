# FF-211 Equipment and events read once per build or export

**Status:** to do · **Group:** 16. Internal improvements

## Why

Building a site or making an export reads the event, camera, lens and film stock from disk again for every frame, though most frames of a roll share them, and an export reads the settings once per frame too.

## What

A site build and an export each list the cameras, lenses, film stocks and events once at the start, into maps by slug, and read the settings once, as the search already does for events. Each frame then looks them up in the maps. Nothing changes in behaviour. _(Recommendation R6 of the architecture review, step 4; after FF-210.)_

## Acceptance criteria

- [ ] `BuildSite` reads the settings once and lists cameras, lenses, film stocks and events once per build or status, not once per frame.
- [ ] `MakeQuickExport` does the same once per export, however many frames it has, including when it writes to a folder through `FolderExports`.
- [ ] A frame whose camera, lens, film stock or event has been deleted is treated as now (the slug isn't found, so the detail is left out as today).
- [ ] The site build, export and folder export API tests pass unchanged; a use case test shows one `listCameras` call for an export of several frames (a counting wrapper written in the test).
- [ ] FF-122's task file says when the index is wanted: when one listing of the real archive, measured, is too slow. After FF-202 and FF-209 to FF-211, a listing costs one pass over the archive, about 225 ms at 300 rolls on the review machine.

## Not in this task

- An index (FF-122 to FF-124).
- Reading each roll once per export: `MakeQuickExport` looks up a frame's roll with `rolls.get` per frame, which since FF-202 reads only that roll.
