# FF-159 Custom roll number pattern

**Status:** to do · **Group:** 2. Library management

## Why

I can have FilmFile suggest roll numbers in the format I use, both when creating rolls and when putting unfiled rolls in order.

## What

Add a separate “Roll number pattern” section to Settings. The archive-wide pattern is saved in `settings.json` and previews a rendered example. Use it for the roll-number suggestion on New roll and for proposed numbers in “Number rolls…”. It depends on FF-153's freeform roll-number support.

## Acceptance criteria

- [ ] Settings has a “Roll number pattern” section with its own Save action, separate from author/copyright. Saving keeps the user on Settings and shows the saved pattern and preview.
- [ ] The default pattern is `{year}-{n:3}`. A settings file without a saved pattern uses this default.
- [ ] A pattern is fixed text, one sequence token with a minimum digit width (`{n:3}`), and optional `{year}`, `{month}`, and `{day}` tokens. Month and day render as two digits. Examples include `{year}-{n:3}`, `{n:4}`, `BP-{year}-{n:2}`, and `{year}{month}-{n:3}`.
- [ ] The Settings section previews the pattern with an example shot date and sequence value. Invalid syntax, missing or repeated sequence tokens, unknown tokens, or a generated label longer than FF-153's 100-character limit is refused with a clear message and changes nothing.
- [ ] The pattern is stored in `settings.json` and exposed through the Settings API. Updating it uses the settings version token; a stale save says “The settings changed since you opened them. Reload the page.” Old settings without the field still load as the default.
- [ ] A New roll opens with a suggested number rendered from the current pattern and shot date. The suggestion updates when the date changes until the user types over the number. If the pattern uses `{month}` or `{day}`, the form requires those date parts.
- [ ] Saving a pattern that uses `{month}` or `{day}` is refused until every existing roll has the required shot-date precision. New and edited rolls must retain the precision the pattern needs.
- [ ] The sequence advances after the highest existing matching value in its token group, never reuses gaps, and skips occupied labels. Its width is a minimum and generated numbers can grow past 999. Counters reset for the distinct date-token values present; without date tokens, one counter runs across the archive.
- [ ] “Number rolls…” proposes labels from the pattern, grouping by the pattern's date-token values. It retains FF-108's shot-date order, filed-roll anchors, active Browse filter scope, and filtered-out occupied labels; without date tokens, numbering uses one global group. Pattern changes alone do not renumber existing rolls.
- [ ] A `POST /api/rolls` request that omits `roll` keeps the existing service-generated default; this pattern changes UI suggestions only. The New roll page sends its suggested value, and “Number rolls…” sends its previewed values.
- [ ] Tests cover settings persistence and legacy defaults, pattern parsing and previews, missing date precision, new-roll suggestions, collisions, and custom-pattern “Number rolls…” previews and saves.

- Applying the pattern to bulk import (FF-154), which can use the shared suggestion behavior when that task is refined.
