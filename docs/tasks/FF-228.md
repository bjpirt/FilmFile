# FF-228 Bring this computer up to date

**Status:** to do · **Group:** 17. Sync and backup

## Why

Knowing when another computer has synced since this one did, and catching up in one click.

## What

When the app opens, it reads the bucket's sync record. If another computer has synced since this one last did, the header warns. "Sync" then works out the direction: down if only the bucket changed, up if only this computer did.

## Acceptance criteria

- [ ] When the app opens with sync set up, and the bucket's sync is newer than this computer's, the header reads "Out of date" with a warning mark. The panel says "MacBook synced on 16 Nov 2026, 15:02, after this computer's last sync on 16 Nov 2026, 11:40."
- [ ] If the bucket can't be reached on opening, the header reads "Couldn't check sync", and the panel has "Check again".
- [ ] "Sync" with only the bucket changed downloads what differs ("Downloading 3 of 3"), moves renamed folders to their new names, and removes files the bucket no longer has, then reads "Synced just now". Files that a `roll.json` still lists are never removed.
- [ ] "Sync" with only this computer changed uploads, as in FF-225.
- [ ] A sync down that fails or is cancelled leaves the library as it was. Downloaded files are checked against the manifest and moved into place only when all have arrived.

## Not in this task

- Both sides changed (FF-231), and the lock (FF-229).

## Notes

- Checking reads only `filmfile/sync.json`.
- Applying a sync down goes through the service (the only writer), with the roll repository's lock held, so no request sees a half-applied sync.
- **Tests:** unit (choosing the direction), API (each direction with the in-memory bucket), web (out-of-date and couldn't-check states), and a journey with two services on one in-memory bucket: change a frame on one, sync, open the other, see "Out of date", sync, see the change.
