# FF-222 Domain types and pure code in the domain

**Status:** to do · **Group:** 16. Internal improvements

## Why

The folder a thing is in should say what it is. What an export is (its recipe, naming, layout and metadata) is defined in two port files; three files of pure code with no ports sit among the use cases; and selections, which exports and events use too, depend on the sites feature for their group labels. None of this breaks a lint rule, but each misleads a reader.

## What

Export types and the pure export code move to a new `domain/exports/`, and the group labels move from `domain/sites/` to `domain/selections/`, with every import updated. Nothing changes in behaviour. _(Recommendation R10 of the architecture review, items 1, 2 and 4.)_

## Acceptance criteria

- [ ] `apps/backend/src/domain/exports/` holds `QuickExport`, `Naming`, `Layout` and `ExportOutput` (now in `application/ports/export-tickets.ts`) and `ExportRecipe`, `ImageMetadata` and `MetadataChoice` (now in `application/ports/image-renderer.ts`), one main export per file, named after it.
- [ ] The two port files keep only their interfaces (`ExportTickets`, `ImageRenderer`) and import the types from the domain.
- [ ] `export-names.ts`, `export-metadata.ts` and `zip.ts` move from `application/use-cases/exports/` to `domain/exports/`, with their tests.
- [ ] `GroupLabel` (now in `domain/sites/site-photo.ts`) and `group-labels.ts` (`rollGroupLabel`, `eventGroupLabel`) move to `domain/selections/`, and the sites code imports them from there. Nothing in `domain/selections/` or `application/use-cases/selections/` imports from `domain/sites/`.
- [ ] Every import is updated; `pnpm verify` passes, including the boundaries lint rules and the coverage floors, with every test unchanged except for its import paths.

## Not in this task

- The error handler's ULIDs and `ListRolls`' second entry point (FF-223).
- Renaming anything: the types and functions keep their names.
