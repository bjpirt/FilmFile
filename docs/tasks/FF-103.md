# FF-103 Choose the version shown

**Status:** done · **Built in:** 6. Versions and scans · **Was:** U62

## Why

A frame's first version, the lab's scan, isn't always the one I want to see once I have better.

## What

In the versions column (U61), each thumbnail has a star at its top left, filled on the version shown everywhere (`defaultVersion`, D15, D46) and outlined on the others. Clicking an outlined star makes that version the one shown on contact sheets, filmstrips, event pages and in the frame view. The star replaces the "Shown everywhere" text label under the thumbnail. The frame view's large image stays on the version being looked at.

## Acceptance criteria

- [x] Each version in the versions column has a star at its top left, always visible: filled on the version shown everywhere, outlined on the others. The star replaces the "Shown everywhere" label under the thumbnail.
- [x] The star is a button named "Show this everywhere" on the others, with the same hover text, and "Shown everywhere" on the filled one; it's in the Tab order and works by touch as well as by mouse.
- [x] Clicking another version's star makes that version the one shown on contact sheets, filmstrips, event pages and when the frame view next opens, saved with `PATCH /api/rolls/{rollId}/frames/{frameId}` (`defaultVersion`) and `If-Match`.
- [x] Clicking a star doesn't change which version the large image shows; clicking the thumbnail still does.
- [x] Clicking the first version's star goes back to the first: the frame records no choice (`defaultVersion: null`), so "the first" still means the first if it's later deleted (D46).
- [x] Clicking the star of the version already shown does nothing, so one version is always shown.
- [x] The star moves at once and is saved in the background, queued with the frame view's other saves so they never clash; the contact sheet, filmstrip and event pages show the new version straight away.
- [x] A save refused because the roll changed (409) puts the star back and shows "This roll changed since you opened it. Reload the page."; any other failure puts it back and shows "Couldn't save it. Is the service running?".
- [x] Deleting the version shown (U28b) puts the first back (`defaultVersion` cleared), and the star is filled on it. (Already built; this is its regression test.)
- [x] A frame with one version shows no versions column, so no star.
- [x] In the "Catalogue a roll" journey: a frame given a second version, then that version's star chosen, shows the second version's picture on the roll's contact sheet after a reload.

## What was built

Each version in the frame view's versions column has a star at its top left (`.version-star`, a button beside the thumbnail's button, drawn by CSS so it adds no text): filled and named "Shown everywhere" on the version shown, outlined and named "Show this everywhere" on the others, `aria-disabled` on the filled one. The old "Shown everywhere" label is gone. Clicking another version's star calls `chooseShown` in `useSaveFrame` (`frames/use-save-frame.ts`): it shows the choice at once in the roll's cached data and the rolls list (so the filmstrip, contact sheets and event pages follow), then saves `PATCH /api/rolls/{rollId}/frames/{frameId}` with `defaultVersion` and `If-Match`, queued with the frame view's other saves; the first version sends `null`. A refused or failed save puts it back and gives the frame view's usual message. The frame view pins the big image to the version being looked at when a star is clicked, so it doesn't move. No API or data change; the web tests' fake service now clears `defaultVersion` when its version is deleted, as the service does.

Tests: frame view tests (the stars and their names, Tab order, choosing, choosing the first, the shown version's star doing nothing, the big image staying, a 409 and another failure, deleting the version shown, a frame with one version), API tests for choosing, clearing and refusing a version the frame doesn't have, and the "Catalogue a roll" journey extended (a second version added to frame 5 and starred; the roll's contact sheet shows it after a reload).

## Not in this task

- Showing the newest Final by itself (not planned).
- A "Show this everywhere" entry in the "⋯" menu: the star replaces it (U28b's menu keeps "Mark as…" and "Delete version…").
- Starring from the contact sheet or the filmstrip; it's done in the frame view only.

## Notes

- Uses the frame's existing `defaultVersion` (D15, D46): the service's `UpdateFrame` already accepts it, checks the version is the frame's own, and `DeleteVersion` already clears it. No API or data change.
- Needs U61 (the versions column), U34 (adding versions) and U28b (deleting one).
- The star sits beside the thumbnail button, over its top left corner (a button can't be inside the thumbnail's button), like the "⋯" menu at its other corner.
- Saving reuses the frame view's `useSaveFrame`, gaining an at-once update of the roll's cached frame like FF-149's `useRateFrame`.
- Tests: frame view tests for the stars, the names and the Tab order, choosing another version, choosing the first (null), the shown version's star doing nothing, the 409 and another failure, the large image staying put, the filmstrip and contact sheet following, and a frame with one version; an API test that `defaultVersion` is saved and cleared; the "Catalogue a roll" journey extended as above.
