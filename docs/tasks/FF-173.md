# FF-173 Mark a frame as in no event

**Status:** done · **Built in:** 4. Metadata

## Why

A few shots at the end of a roll, after an event, may not belong to any event. Today a frame with no event of its own is in its roll's event, so they can't be left out of it, and anything that works by event, such as a site, would miss them or lump them in with the wrong one.

## What

A frame's Event field gets a "No event" choice beside "Same as roll" and the events, on the frame page and in bulk edit on a roll's or an event's page. A frame marked so is in no event, even when its roll has one. It's kept as the frame's own `event` being `false` (D98). Everywhere that groups or finds by event treats those frames as in none, and a site or export grouped by event puts every frame in no event, marked or never given one, under "No event set" (FF-120).

## Acceptance criteria

- [x] The frame page's Event field offers "The roll’s: Iceland 2026" (the default: the frame is in its roll's event), "No event" and each event; choosing "No event" saves it, and the frame page and the roll page then say "No event" for it.
- [x] A frame marked "No event" on a roll that has an event is not in that event: it's missing from the event's page and its count, it's shown under "No event" on its roll's page, and the rolls page's "Group by Event" and the browse panel's counts leave it out of that event.
- [x] Choosing "The roll’s: …", or the reset "Use the roll’s event", on it puts it back in its roll's event.
- [x] In bulk edit on a roll's or an event's page, Event has "No event" too, and says "Event set on 3 frames." as it does for an event.
- [x] A frame's resolved details leave the event out when it's "No event" (its roll's isn't used), so nothing written from them, such as exports' XMP and EXIF, has an event for it.
- [x] `false` is accepted only as a frame's own event: the service refuses it for a roll, with the usual message.
- [x] A frame whose `event` is `false` in `roll.json` is read as in no event, and saving the roll keeps it byte-for-byte; frames with `null` (today's files) are unchanged.
- [x] Reworded: the grouping and the rule are built with the site (FF-120, FF-119), which read a frame's event through `eventsOfFrame` and the resolved details, so a frame marked "No event" is in none there too.

## Not in this task

- A frame in no event on a roll that has none (it's the same as never given one; nothing to mark).
- Making "no event" a rule in a site or export's selection (FF-119, a later choice).

## Notes

- D98: a frame's own `event` is a slug, `null` for the roll's (as today) or `false` for none. The type is `Slug | null | false`, so a check that forgets `false` is a type error, not a string to special-case.
- One helper beside each of `eventsOfFrame` (`apps/web/src/events/frame-events.ts`) and the backend's frame layer (`domain/details/layers.ts`) turns it into the three cases, so nothing else reads it directly.
- Contracts and the persistence schema: the frame's `event` accepts a slug, `null` or `false`; the roll's accepts a slug or `null`.
- Tests: the layers and resolver, `eventsOfFrame` and `eventsOfRoll`, the frame and roll page tests, bulk edit, the API's validation; the "Bulk edit" journey extended.

## What was built

A frame's `event` is `Slug | null | false` (D98): the domain's `Frame`, the contracts' frame, update-frame and bulk-details requests, and `roll.json`, where a frame in no event stores `"event": false` and one with none of its own says nothing. `UpdateFrame` and `UpdateFrames` take `false`; a roll's event still can't (the service answers 422). In the frame layer of the details resolver `false` clears the event the roll gave, so the resolved details leave it out. The web app's `eventsOfFrame` and `eventsOfRoll` treat `false` as no event, so the roll page's "No event" group, the event pages, the rolls page's grouping and the browse panel's counts follow. The frame page's Event field has a "No event" choice (and the reset, "Use the roll’s event", then shows), the Set menu's Event form has it for the frames selected, and a frame marked so says "Its own event" on the contact sheet when its roll has one. Tests: the layers, roll file, the two use cases and the API in the backend; `frame-events`, `own-details`, the frame view and the roll page in the web app; the "Bulk edit" journey extended.
