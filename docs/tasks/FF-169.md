# FF-169 Edit an event from its page

**Status:** done · **Built in:** 4. Metadata

## Why

Viewing an event, I should be able to rename it or change its date from there, not only from the Events page's cards.

## What

An "Edit" button in an event page's heading opens the same form the Events page's cards use, above the frames.

## Acceptance criteria

- [x] An event's page has an "Edit" button (named "Edit Iceland 2026") in its heading, beside "Group by".
- [x] It opens the event's form ("Edit Iceland 2026": name, date, "Save event", "Cancel") above the frames, and the button goes while the form is open.
- [x] Saving renames the event or changes its date, against its version token (`If-Match`), and the heading and the Events page show the change; the form closes.
- [x] Cancel closes the form and changes nothing.
- [x] An event changed elsewhere since it was opened says "This event changed since you opened it. Cancel and edit it again." and keeps what's there; a name already used and a date that doesn't exist are refused as on the Events page.

## Not in this task

- Changing an event's slug (it never changes) or deleting an event.

## What was built

`events/event-editor.tsx` (`EventEditor` and `problemWith`, moved out of `events-page.tsx` so both pages share them) is used by the Events page's cards and by `events/event-page.tsx`, which has the "Edit" button in its heading and shows the editor between the heading and the frames. Page tests cover opening it, saving a new name (and the heading following), cancelling and a changed-elsewhere refusal.
