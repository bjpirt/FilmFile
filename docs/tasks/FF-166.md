# FF-166 Choose where downloads are saved in the desktop app

**Status:** to do · **Group:** 12. Exports

## Why

An export saved straight to where the files are wanted (a Lightroom folder, Dropbox, an external drive, a print shop's USB stick), not left in Downloads.

## What

In the desktop app, a download (a quick export's JPEG or zip, FF-165, or any other file the app downloads) asks where to save it, with the computer's own save dialog, starting at the last place used. A browser keeps doing what it does.

## Acceptance criteria

- [ ] In the desktop app, downloading a quick export opens the save dialog with the suggested name (`2026-014-12A.jpg`, `2026-014 Westfjords.zip`), starting in the folder last saved to (Downloads the first time).
- [ ] Choosing a place saves the file there and remembers its folder; cancelling the dialog cancels the download and the work.
- [ ] When it's saved, the app says "Saved to /Users/ben/Pictures/Iceland/2026-014 Westfjords.zip" with a "Show in Finder" button.
- [ ] The last folder is remembered by the app, per computer (D52).
- [ ] A browser's downloads are unchanged.

## Not in this task

- Saved exports (FF-117), which are always made in `Exports/<slug>/` in the FilmFile folder.
- A folder chosen once and exported to again without asking.

## Notes

- D95. The desktop app handles the window's `will-download` event and shows its own dialog (`dialog.showSaveDialog`), so the service is never told a path: it writes nothing outside its own folder (CLAUDE.md, the `security-rules` skill), and the page can't ask the app to save anywhere.
- Tests: the download handler (the suggested name, the remembered folder, a cancelled dialog) as a unit test over fakes, and a desktop journey that answers the save dialog, as the others do.
