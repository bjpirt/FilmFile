# FF-167 Export selected frames

**Status:** to do · **Group:** 12. Exports

## Why

A roll's best frames as files in one go, for a print shop or to send on, picked by clicking them.

## What

On a roll's page, the selection bar gets an "Export…" button, opening a dialog with the single frame's choices and a layout and file names; the selected frames are made and downloaded the normal browser way, as one zip. The roll page's "Bulk edit" becomes "Bulk actions", since the selection now does more than edit.

## Acceptance criteria

- [ ] A roll's Actions menu item "Bulk edit" is now "Bulk actions" (and its selection bar, messages and tests say so); while selecting, the bar has an "Export…" button beside "Set" and delete, disabled until frames are selected, opening "Export 12 frames".
- [ ] The dialog has the single-frame export's "Size", "Quality" and "Metadata" (FF-165, FF-118), "Layout" (Flat, A folder per roll, or Year then roll) and "File names" (a pattern of `{roll}`, `{frame}`, `{title}`, `{year}` and `{original}`, `{roll}-{frame}` at first), remembered with the other last-used choices.
- [ ] Frames that have no version to make a file from are listed in the dialog before anything is made ("2 frames have no scan and will be left out").
- [ ] "Export" downloads one zip named for the roll (`2026-014 Westfjords.zip`) holding a JPEG of each selected frame, made as in FF-165 and laid out and named as chosen; names that would be the same get a `-2`, `-3` after them.
- [ ] The zip is sent as it's made, one file after another, so it starts downloading at once and the browser shows its own progress, and cancelling the download stops the work.
- [ ] A frame that can't be made is left out and listed in a `skipped.txt` in the zip with why.
- [ ] A failure before the download starts says what went wrong without internals.

## Not in this task

- Selecting on an event's page (FF-168), and saved exports (FF-116, FF-117).
- Choosing where the zip is saved: the browser's, or in the desktop app FF-166.

## Notes

- D95. The same request and single-use download address as FF-165 with several frames; the layout and names are the saved export's (FF-117), written once as shared code.
- The zip is a store-only one (JPEGs don't compress), written as a stream: a few dozen lines with `zlib.crc32`, no dependency; the service writes nothing to disk.
- Tests: the dialog, the rename and button, the use case and API (names, a frame with no version, the zip read back with its layout and `skipped.txt`), and a journey: select frames on a roll, export and find the zip's files.
