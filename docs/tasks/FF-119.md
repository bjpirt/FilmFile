# FF-119 Sites

**Status:** to do · **Group:** 13. Sites · **Was:** U97

## Why

I want to share a chosen set of photographs as a site, and say what goes in by describing it ("Iceland 2026, rated 4 stars and up"), not by picking frames one at a time.

## What

A Site is a saved definition: a name and a selection of frames (FF-164: rules, and frames always or never included by hand) and, with FF-120, how it's built. A "Sites" page lists them; a site's page edits its selection and shows the frames that match as they change. Always live: the frames are worked out from the archive as it is now. Building the site is FF-120.

## Acceptance criteria

- [ ] A "Sites" link in the header, after Exports, opens a page listing the sites by name, each linking to its page with its frame count ("24 frames"), and a "New site" button asking for a name; with no sites it says "No sites yet. Make one to share a set of frames." beside the button.
- [ ] A new site has no rules, so every frame matches (except hidden frames, D99), and its page opens straight away.
- [ ] A site's page has its name (changeable) and its selection: the rule editor, "24 frames match" and the grid, as on Find frames (FF-164), with "Always include" and "Never include" on each frame, and a "Hidden: 2" line listing those left off with a "Put back" for each. A frame left off by hand is not in the grid or the count.
- [ ] Each change on a site's page (name, a rule, a frame included or left off) is saved straight away, against the site's version token; there is no Save button.
- [ ] A name makes the site's slug (`iceland-highlights`), unique among sites; creating or renaming to one that exists says so. Renaming changes the slug, so the file moves to the new slug and the page's address follows; a folder already built in `Sites/` under the old slug is left where it is.
- [ ] Deleting a site asks "Delete site Iceland highlights?" and moves its definition to the archive's `deleted/`; a folder it built in `Sites/` is left where it is.
- [ ] A site is saved as `Library/sites/<slug>.json` with its ID, name and `selection`, against its version token; one changed elsewhere says "This site changed since you opened it. Reload the page." and keeps what's there and what's on screen; writing it again with nothing changed leaves the file byte-identical.
- [ ] A frame that was included or left off by hand and has since gone from the archive is skipped in the count and grid, and its entry stays in the site's file.
- [ ] `GET /api/sites`, `POST /api/sites`, `GET`, `PATCH` (with `If-Match`) and `DELETE /api/sites/{slug}`; the matching frames come from `POST /api/frames/search` (FF-164) with the site's selection.
- [ ] Journey: make a site, add a rating rule and see the count change, include and leave off a frame, rename it, reload and find it all kept, then delete it.

## Not in this task

- Building the site (FF-120).
- Publishing it (FF-121).
- More than one gallery, or sections, in a site.
- Adding frames to a site from the roll and event pages, or making a site from the Browse filters (FF-162, FF-163).
- Build options and "built" state on the record (FF-120 adds them as optional fields).
- A count of frames no longer in the archive, or a way to clean those entries out.

- The rules, rule editor, count and grid are FF-164's; this task adds the record and its pages, as FF-116 does for exports.
