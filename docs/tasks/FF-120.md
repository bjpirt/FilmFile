# FF-120 Build a site

**Status:** to do · **Group:** 13. Sites · **Was:** U98

## Why

Sharing the frames I've chosen as a simple website that works from any host, or from the folder it's in.

## What

"Build site" on a site's page (FF-119) writes a self-contained static site of its matching frames into `Sites/<slug>/`: a gallery in one page, grouped by roll or event if chosen, with a lightbox. It's always built from the archive as it is now, and only what changed is made again: the page says whether the site is up to date, and each image is made again only when what it's made from changed.

## Acceptance criteria

The site:

- [x] "Build site" writes `Sites/iceland-highlights/` holding `index.html`, `assets/` (one stylesheet and a small script), `images/` and `site.json` (the manifest), and says "Site built in Sites/iceland-highlights: 24 photos (3 images made, 69 unchanged)."
- [x] `index.html` shows the site's title and intro text, and its frames in shot order as a grid; with "Group by Roll" or "Group by Event" the grid is split under headings (the roll's number and name, or the event's name and date), in the order of their first frame; every frame in no event, whether marked "No event" (FF-173) or never given one, is last under "No event set".
- [ ] Clicking a photo opens it larger in a lightbox, with the previous and next ones, the arrow keys and Esc, and its caption; it works on a phone. *(Built and journey-tested with a click and Esc; swipe and the phone layout not yet checked on a phone.)*
- [x] The site's own options, on its page and kept in the site: title (the name unless changed), intro text, Group by (Nothing, Roll or Event), and which of title, date shot, camera, lens and film stock appear in captions (title only, at first).
- [x] The site needs nothing from the internet and works opened straight from the folder, and from any folder or address it's put at (every link is relative).

Images and privacy:

- [x] Each photo is made from the frame's version shown, turned as it's shown, at a few widths for different screens (`srcset`), as JPEGs; originals are never copied, and a raw version shown is made from the largest preview it carries.
- [x] No GPS or other location is in the images or the pages, and an image's metadata is only the author and copyright.
- [x] The images use the same rendering as exports (FF-165, FF-118), so the version shown, the turn and the metadata rule are one piece of code.

Up to date, and made again:

- [x] Each image's file name holds a hash of what it's made from (the version's own hash, its turn, the width and the rendering's version), so an image is made again only when one of those changed, and one no longer needed is removed.
- [x] `site.json` records the frames on the site and what each image was made from, and the site's page says "Not built yet", "Up to date", or "Out of date: 3 frames added, 1 removed, 2 changed", by comparing it with the frames now matching, their images' hashes and the site's options.
- [x] Building a site that's up to date changes nothing: no file is rewritten and the folder is byte-identical.
- [x] A frame rated down, rotated, given another version to show, deleted or moved to another event makes the site out of date, as the rules and its options do; the page says how many frames were added, removed or changed (it doesn't name them yet).

Safe to run:

- [x] A build is made in a folder beside the site's and swapped in when it's done, so a failed or cancelled build leaves the site as it was, and an upload of the folder never sees half a site.
- [x] While it runs the page shows "Making images: 12 of 40" and a "Cancel" button.
- [x] If `Sites/<slug>/` already holds something with no `site.json`, building says "Sites/iceland-highlights holds something else" and changes nothing; files in `Sites/` that aren't a site's folder are left alone.
- [x] A site with no matching frames builds an empty page that says so, after asking "This site has no frames. Build it anyway?".
- [ ] "Open site" shows the built `index.html` in the browser, served read-only by the service under the site's name and through the safe-path helper (no other file is ever served from `Sites/`); in the desktop app, File › Show FilmFile Folder in Finder also reaches the folder. *(Served at `/built-sites/<slug>/`, opened in a new tab and journey-tested in the browser; how the desktop app's window handles the link is not yet checked.)*

## What was built

- `domain/sites/`: `renderSite` (page, stylesheet with a class for each photo shape so no inline styles are needed, script), `planSiteBuild` and `describeSiteStatus`, the sizes and hashed names of images; `BuildSite` (with `status`), `SiteBuilds` (background jobs per site: start, status, cancel) and `GetBuiltSiteFile` in `application/use-cases/sites/`; `SiteFolders` with in-memory and filesystem adapters (a build is made in a hidden folder and renamed into place).
- Routes: `POST /api/sites/{slug}/build`, `GET /api/sites/{slug}/status`, `DELETE /api/sites/{slug}/build`, and `GET /built-sites/{slug}/…` for opening a built site (its page, `assets/` and `images/` only).
- A site's record gained `presentation` (title, intro, group by, captions), stored only once it differs from the plain default (D102).
- The site's page gained "How it looks" and a Build section: the status, "Build site", "Making images: 12 of 40" with "Cancel", the "Site built in …" summary and "Open site".
- Journey: `test/e2e/build-site.e2e.ts`.

## Not in this task

- Publishing it (FF-121): upload is another step, with other tools or FF-121's.
- Themes, other layouts, sections, watermarks, a download link for full size.
- The choices an export has (size, quality, layout, names, metadata, FF-117, FF-118): the site's widths are its own fixed set, and its metadata is only the author and copyright.

## Notes

- Replaces D61 (D92). Needs FF-119 (the site and its frames) and the image rendering made for exports (FF-165, FF-118); it doesn't need FF-117, since a site's `site.json` records its own inputs.
- The pages are pure functions (the frames, options and image names in; files out), tested without a browser; the script is a couple of kilobytes of plain JavaScript with no dependency.
- Deterministic: the same inputs make byte-identical files, which keeps uploads small (FF-121 sends only what `site.json` says changed).
- API: `POST /api/sites/{slug}/build` (progress and cancel), `GET /api/sites/{slug}/status` (the state above); the options are part of the site's record (FF-119's `PATCH`).
- Journey: make a site of two rolls' frames, build it, open its index in the browser and find the photos.
