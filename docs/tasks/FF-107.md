# FF-107 Mark a roll as filed

**Status:** to do · **Group:** 2. Roll numbers · **Was:** U92

## Why

Once a roll's negatives are in the physical archive with its number on the sleeve, the catalogue must never move that number, or the shelf and the catalogue disagree.

## What

"Mark as filed" in a roll's Actions menu fixes its number. A padlock marks it in the roll page's frame thumbnails and after its number in the page heading; in Edit details, the number stays visible but can't be changed. "Unmark as filed…" is available when it needs correcting. The padlock in the thumbnails describes the roll, not the individual frames.

## Acceptance criteria

- [ ] "Mark as filed" in Actions marks the roll immediately, using the loaded ETag. Its number and folder stay the same; `roll.json` gains `filed: true`.
- [ ] A filed roll shows a padlock named and titled "Filed" after its number in the roll page heading.
- [ ] Each frame thumbnail on a filed roll's page shows the same "Filed" padlock in the existing frame-marks group as the own-details and versions icons. The padlock describes the roll, not that frame. Roll cards, list rows, event pages and the filmstrip do not show it.
- [ ] In Edit details, a filed roll's number is visible as non-editable text, followed by the "Filed" padlock, with "Filed: unmark it to change the number."
- [ ] "Unmark as filed…" opens an in-page confirmation with "Only unmark it if its negatives aren't filed under this number.", and "Unmark as filed" and "Cancel" buttons. Confirming removes `filed` from `roll.json`; it does not rename the folder.
- [ ] Marking or unmarking a roll changed elsewhere since the page loaded is refused with 409; the page says "The roll changed since you opened it. Reload the page." and changes nothing.
- [ ] A filed roll's number can't be changed by hand (FF-106) or by Number rolls (FF-108). Both APIs refuse a request to change an already-filed roll's number with 422 and "A filed roll's number can't be changed." A stale ETag remains a 409.
- [ ] The roll API always returns `filed` as a boolean; `PATCH /api/rolls/{rollId}` accepts an optional boolean `filed` to mark or unmark the roll.
- [ ] `roll.json` writes `filed: true` only when set; an absent field, including in an older file, means unfiled.

## Notes

- Decisions D66 (folder names), D68 (filed numbers never change), D71 (stored and API representation and error status), and D72 (padlock and confirmation).
- A missing `filed` field defaults to `false` in the domain model; adding this optional field needs no migration. Saving `false` removes the field so unchanged unfiled rolls remain byte-identical.
- Filing changes only `roll.json`; it never renames the roll folder (D66). Deleting a filed roll remains allowed after the existing confirmation (D38).
- Tests: repository and API tests for marking, unmarking, defaulting old files, ETags, and refused number changes; roll-page tests for the actions, icons and conflict. The FF-108 journey already covers filing a roll, so this task adds no journey.
