# FF-210 A site's build status reads the archive once

**Status:** to do · **Group:** 16. Internal improvements

## Why

The site page asks for its build's status again and again while a build runs, and each time the archive is read twice over: once to find the site's frames, and again inside `BuildSite.status` to gather what each frame is.

## What

Finding a site's frames and gathering them share one read of the rolls. `SiteBuilds` passes the rolls it read to `BuildSite`, so a status, and the start of a build, read every roll once. Nothing changes in behaviour. _(Recommendation R6 of the architecture review, step 3; after FF-209.)_

## Acceptance criteria

- [ ] `SiteBuilds.status` reads every roll once per call, not twice.
- [ ] `SiteBuilds.start` reads every roll once for its status check, and the build itself (`BuildSite.execute`) reads it no more than once more.
- [ ] `BuildSite`'s signature stays simple: it takes the rolls already read as one more field of its input (or `SiteBuilds` passes what it loaded another plain way), with no cache object.
- [ ] Every site build and site status API test passes unchanged.
- [ ] A use case test shows the number of `list` calls on the roll repository for one status: one. (A counting wrapper round the in-memory repository, written in the test, not a mocking library.)

## Not in this task

- Equipment and event lookups per frame (FF-211).
- Caching between polls: each status still reads the archive as it is now.

## Notes

- `SiteBuilds` is `apps/backend/src/application/use-cases/sites/site-builds.ts`. `#framesOf` (about line 83) calls `SearchFrames.execute`, which lists every roll. `start` (about line 113) and `status` (about line 208) then call `this.#building.status(ctx, { slug, frames, options })`.
- `BuildSite` is `apps/backend/src/application/use-cases/sites/build-site.ts`. `status` (about line 131) and `execute` (about line 150) both call `#gather` (about line 223), which reads settings and lists every roll into a `Map` by ID.
- After FF-209, `SiteBuilds` can load the rolls, settings and event labels itself and call `findFrames`, then hand the same rolls (and settings) to `BuildSite`. Choose whichever way leaves `BuildSite`'s input simplest, and say which in What was built.
- `#gather`'s comment says reading rolls one by one costs a pass over the archive each. Since FF-202 that's no longer true (a roll is found by its folder); listing once is still right for a site of hundreds of frames, so reword the comment to say why.
