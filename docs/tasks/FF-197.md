# FF-197 The Windows app

**Status:** to do · **Group:** 10. Desktop app

## Why

Running FilmFile on Windows.

## What

`pnpm package` on Windows makes the app as a zip, `FilmFile-<version>-win-x64.zip`: unzip it anywhere and run `FilmFile.exe`. CI builds and checks it in `package.yml`, so releases include it. _(Split from FF-139.)_

## Acceptance criteria

- [ ] On Windows, `pnpm package` makes `FilmFile-<version>-win-x64.zip`, holding the `FilmFile` folder with `FilmFile.exe`, which opens FilmFile in its own window.
- [ ] The app has FilmFile's icon (`build/icon.ico`, made from `icon.svg` by `make-icon.sh`) on its window, its taskbar button and `FilmFile.exe`.
- [ ] Its fuses are set as on a Mac, and sharp's native files are outside its app archive.
- [ ] Its menu has File (with "Quit"), Edit, View, Window and Help (with "About FilmFile", FF-194), File has "Show FilmFile Folder in Explorer", and the Library's own menu says "Show in Explorer".
- [ ] `package.yml` builds it on `windows-latest` and runs the packaged-app journey there (the service starts, the UI is served, a roll is made and its scans get thumbnails), so the next release includes it.

## Not in this task

- An installer, Start menu entry or uninstaller. Those come with updates (FF-138), which need a Squirrel installer on Windows.
- Signing (FF-199). Until then SmartScreen warns on the first run ("More info" › "Run anyway").
- Windows on Arm.

## Notes

- Needs FF-196 first. The zip is made with PowerShell's `Compress-Archive` or Node, with no new dependency (D110).
- `package.ts` gains a Windows branch: no `.icns`, `ditto` or `hdiutil`, and no `resetAdHocDarwinSignature`.
