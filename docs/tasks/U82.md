# U82 FilmFile opens in its own window

**Status:** done · **Built in:** Desktop app

## What was built

`apps/desktop` (`@filmfile/desktop`, Electron 45): its main process (`main.ts`) starts the service's own `main.ts` in a `utilityProcess` on a free port of `127.0.0.1` (`free-port.ts`, `start-service.ts`), waits for `/api/health` (`wait-for-service.ts`), and opens a window on it titled FilmFile (`open-window.ts`). Closing the window quits, and quitting stops the service as Ctrl+C would, so saves in progress finish. Only one copy runs: opening it again brings the window forward. The archive comes from `FILMFILE_ARCHIVE`; without it, the app says so and quits. The window has context isolation, the sandbox, no Node.js and no preload; permission requests are refused; and links and new windows going elsewhere open in the default browser (web links only). Electron's standard menus are kept. `pnpm desktop` builds the UI and runs it from source. Journeys (`desktop.e2e.ts`, a project of its own): the app opens on the Rolls page, its page has no Node.js and can't open windows, and quitting stops the service; opening it again starts no second copy. CI runs them under `xvfb` with Ubuntu's user-namespace limit lifted for Electron's sandbox. Electron runs the TypeScript as it is, so nothing is bundled yet; a top-level `await` in the main file would stop Electron's `ready` from firing, so there is none.
