# FF-152 New rolls numbered automatically

**Status:** to do · **Group:** 2. Roll numbers

## Why

Importing a pile of rolls shouldn't stop at working out each one's number first: they get one straight away and are put in order later (FF-108).

## What

A new roll gets the next free roll number, from its date shot's year if it has one, otherwise this year's, filled in on New roll and changeable there or later (D67). *(Replaces D8, under which the service never invented a number.)*

## Acceptance criteria

- [ ] New roll's Roll number field starts with the next free number for this year, e.g. `2026-015` when `2026-014` is the highest, and changes to that year's next free number when a date shot in another year is entered, until the number is typed over.
- [ ] A number typed by hand is kept, and checked as now (`YYYY-NNN`, not taken).
- [ ] The API takes a new roll with no number and gives it the next free one for its date shot's year, or this year's; the created roll says which.
- [ ] The next free number is one more than the highest of that year, so gaps left by deleted rolls aren't reused.
- [ ] Two rolls created at once never get the same number.

## Not in this task

- Numbering many rolls in date order (FF-108).
- Patterns other than `YYYY-NNN` (FF-153).
- Importing many rolls at once (FF-154).

## Notes

- Decision D67. A number given automatically is provisional like any other until the roll is filed (FF-107).
- API: `POST /api/rolls` with `roll` optional.
