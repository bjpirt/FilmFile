# FF-198 The Linux app

**Status:** to do · **Group:** 10. Desktop app

## Why

Running FilmFile on Linux.

## What

`pnpm package` on Linux makes an AppImage, `FilmFile-<version>-linux-x64.AppImage`: one file that runs on most distributions with nothing to install. CI builds and checks it in `package.yml`, so releases include it. _(Split from FF-139.)_

## Acceptance criteria

- [ ] On Linux, `pnpm package` makes `FilmFile-<version>-linux-x64.AppImage`. Once it's made executable, it opens FilmFile in its own window.
- [ ] The AppImage has a desktop entry ("FilmFile", category Graphics;Photography) and FilmFile's icon (`build/icon.png`, made from `icon.svg` by `make-icon.sh`).
- [ ] Its fuses are set as on a Mac, and sharp's native files are outside its app archive.
- [ ] `package.yml` builds it on `ubuntu-latest` and runs the packaged-app journey there under xvfb, so the next release includes it.
- [ ] `appimagetool` is downloaded at a fixed release and checked against its SHA-256 before it's run.

## Not in this task

- `.deb`, `.rpm`, Flatpak or Snap packages.
- Updates: Electron's `autoUpdater` doesn't support Linux (FF-138).
- Linux on Arm.

## Notes

- Needs FF-161's `package.yml`. AppImage chosen for one file covering most distributions (D110).
- `appimagetool` is a build tool, not a dependency of FilmFile's. Pinning it by checksum is the CI equivalent of pinning actions by SHA (`security-rules`).
- glibc distributions only: sharp's musl files (Alpine) aren't included.
- The menus keep their plain words ("Show FilmFile Folder", "Show in Folder"), since the file manager varies.
- Ubuntu 24.04 needs the user namespace setting the end-to-end job already sets, for Electron's sandbox.
