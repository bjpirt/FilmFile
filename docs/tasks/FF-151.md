# FF-151 Roll folders named by number and ID

**Status:** to do · **Group:** 2. Roll numbers

## Why

Rolls are renumbered freely before their negatives are filed (FF-106, FF-108), often several at once and swapping numbers. A roll's folder named only by its number would clash with another's during a swap (2026-014 ↔ 2026-015). Naming every roll's folder by its number and its ID keeps names unique while they're renamed, and still says the number in Finder.

## What

Every roll's folder is `rolls/YYYY/YYYY-NNN-<ID>/`, its number and the last 8 characters of its ULID, hyphenated (e.g. `rolls/2026/2026-014-Q2P7RM4K/`), filed or not, and the roll repository renames it whenever a save changes the roll's number (D66). A roll is found by the `roll.json` in its folder, never by the folder's name; the paths in `roll.json` are inside the roll's folder, so renaming it changes nothing in the file. FF-106 and FF-108 add the ways to change a number, and use this renaming. *(Replaces D10's rule that a roll's folder is its number alone.)*

## Acceptance criteria

Naming and finding:

- [ ] A new roll's folder is `Library/rolls/<year of its number>/<number>-<last 8 characters of its ID>/`, e.g. `rolls/2026/2026-014-Q2P7RM4K/`, with its `roll.json`, `frames/` and `.state.json` in it as now.
- [ ] Rolls are found by the `roll.json` in their folder, whatever the folder is called: `2026-014-Q2P7RM4K`, `2026-014` (made before this task), or a name that no longer matches the number (an interrupted rename).
- [ ] Rolls already in folders named by number alone stay where they are and keep working until their number changes.
- [ ] Adding a version, deleting a frame or version, and deleting a roll find the roll's folder by its ID, wherever it is and whatever it's called.

Renaming:

- [ ] Saving a roll with a different number renames its folder to `<new number>-<ID>`, moving it to the new number's year folder if the year changed; an old-style folder is renamed the same way.
- [ ] Two rolls swapping numbers are both renamed without either name clashing.
- [ ] A year folder left empty, by a roll moving out or being deleted, is removed; a year folder with anything in it never is.
- [ ] Adding a version to a roll while its number changes never loses the file or puts it in the wrong folder: uploads to a roll and renames of it take turns.
- [ ] Nothing the API returns, and nothing the UI shows, changes; no response gives a folder or path.

## Not in this task

- Ways to change a roll's number: by hand (FF-106) and Number rolls (FF-108).
- Frame and version folders named by number and kind (FF-155).
- Recovering a folder whose rename was cut short (FF-156).
- Moving existing rolls into the new naming before their number changes.

## Notes

- Decision D66. Filing (FF-107) renames nothing: the number just stops changing.
- A rename changes the folder's path, so backup and sync see its files as new, and links into it are rebuilt (the NegPy folder, FF-112); renumbering mostly happens while a roll holds only the lab's small scans.
- Through the `RollRepository` port, whose `save` renames when the number changes; the blob store and holding area find a roll's folder by its ID (by the `roll.json` in it) rather than work it out from the number, and share the roll's lock for writing into it.
- The folder is renamed first, then `roll.json` saved in its new place: a rename cut short leaves a folder whose name doesn't match its number, which is still found, and renamed the next time the number changes.
- Tests: the roll repository's contract suite (new rolls, old-style folders, renaming, moving year, swaps, empty year folders, an interrupted rename), the blob store's and holding area's tests for both namings and for an upload during a rename, and API tests; the journeys run unchanged.
