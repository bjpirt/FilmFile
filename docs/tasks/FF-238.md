# FF-238 Renames and removals in the backup

**Status:** to do · **Group:** 17. Sync and backup

## Why

After the first backup (FF-225), the bucket should follow the library as it changes: a renumbered roll or frame shouldn't be uploaded all over again, a file emptied from `deleted/` shouldn't stay in the backup for ever, and a file gone missing from this computer must never take the backup's copy with it.

## What

Sync copies a renamed file inside the bucket instead of uploading it again, removes from the bucket the files emptied from `deleted/` (saying so first), and keeps any file `roll.json` still lists that's missing on this computer, saying so. _(Split from FF-225.)_

## Acceptance criteria

- [ ] A file whose folder was renamed (a renumbered frame or roll, a version's changed kind), matched by its SHA-256, is copied inside the bucket from its old path, not uploaded again, and its old path is removed. While copies run, progress reads "Copying 12 of 36 renamed files".
- [ ] Files emptied from `deleted/` by hand are removed from the bucket. Before the sync starts it says "This sync will also remove 3 files emptied from deleted/ from the backup." with "Sync" and "Cancel"; "Cancel" changes nothing.
- [ ] A file that a `roll.json` lists but that is missing from the library is never removed from the bucket. The sync finishes and says "2 files listed in the library are missing on this computer. The backup still has them."
- [ ] Removals come after uploads and copies, and before the manifest and sync record; a sync cut short during them leaves the record as it was.

## Not in this task

- Syncing down, and what another computer removes (FF-228).

## Notes

- **Decisions:** D117 (a file leaves the bucket only when no `roll.json` lists it and it's gone from the library; a listed file that's missing is damage).
- **Requests:** the bucket port gains copy (S3's `CopyObject`, `x-amz-copy-source`), and uses FF-201's delete-many.
- **Tests:** unit (planning copies and removals from the library and the last manifest), contract (copy), API, web (the confirmation and the missing-files message), and the FF-225 journey extended: renumber a frame and sync, seeing a copy and no upload.
