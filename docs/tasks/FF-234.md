# FF-234 The site page's Publish section

**Status:** done · **Built in:** 13. Sites

## Why

Publishing a site, and seeing whether what's on the web matches it, from the site's own page. _(Split from FF-201, which is built; needs FF-236 first.)_

## What

A "Publish" section on the site's page, below Build. It always shows where the site goes, in two fields saved together with "Save": a bucket used only for this site, in the Cloudflare account set in Settings (FF-236), and the address the site is seen at. Under them it says whether what's in the bucket matches the site, with "Publish" (building first as needed, with progress and "Cancel"), "Unpublish…" (after asking) and "View site".

## Acceptance criteria

- [x] The site's page has a "Publish" section below Build, with fields "Bucket" and "Address" and a "Save" button, then the section's state and its buttons. The Bucket field's hint reads "Use a bucket only for this site: files it doesn't have are removed."
- [x] "Save" is enabled when both fields are filled in and differ from what's saved, or when both are empty and a target is saved. Saving both empty takes the target away; nothing is unpublished.
- [x] With no target saved, the section reads "Say where to publish the site." and "Publish" and "Unpublish…" are disabled. With no Cloudflare account ID in Settings, it reads "Set your Cloudflare account ID in Settings." with an "Open Settings" link, and the same buttons are disabled. The fields can still be filled in and saved.
- [x] Saving a different bucket while the site is published says "The site stays in old-bucket until you empty it in Cloudflare." Nothing is asked, and nothing is removed from the old bucket.
- [x] A field the service refuses says why under it, in the service's words (for example "must be an https:// address"), and nothing is saved. The address is kept and opened as typed.
- [x] When the page opens with a target saved, and after the target is saved, the section says how the bucket stands: "Not published", "Published 13 Nov 2026, 14:02, up to date" or "Published 13 Nov 2026, 14:02: 12 files to update" (1 file: "1 file to update"), the time in this computer's time zone. While it's asking it reads "Checking what's published…". With nothing built it reads "Not built yet: Publish builds it first." After a build, publish or unpublish it asks again.
- [x] When the bucket can't be asked, the failure's message shows where the state would be (for example "Couldn't reach Cloudflare. Are you online?"), with a "Check again" button; "Publish" stays enabled. Nothing is retried on its own. Missing keys show here too, from the check ("No [filmfile] profile in ~/.aws/credentials, so the site can't be published."); the page doesn't look at Settings' `cloudflareKeysFound` first.
- [x] Where what's wrong is fixed in Settings (no account ID, no `[filmfile]` keys, keys refused), whether from the check, a publish or an unpublish, the message is followed by an "Open Settings" link. Other failures (no bucket, offline, anything else) have none.
- [x] "Publish" builds the site first when it isn't built or is out of date ("Making images: 12 of 40"), then uploads ("Uploading 12 of 40") and removes what's gone ("Removing old files: 3"), with "Cancel" throughout. When it's done the state reads "Published 13 Nov 2026, 14:02, up to date". A cancelled publish reads "Publishing cancelled."
- [x] Publishing a site with no frames asks first: "This site has no frames. Publish it anyway? Everything else in photos-pirt is removed.", with "Publish" and "Cancel".
- [x] A failed publish shows the service's message followed by "Files already uploaded stay." (for example "Cloudflare refused the keys in the [filmfile] profile. Files already uploaded stay."). A publish that stopped because the site couldn't be built shows "Couldn't build the site, so it wasn't published." alone.
- [x] "View site" opens the address in a new tab whenever the site is published ("up to date" or "files to update").
- [x] "Unpublish…" asks "Unpublish Iceland? This removes 2,104 files from photos-pirt.", with "Unpublish" and "Cancel", then reads "Not published". A failure shows the service's message. With nothing published it's disabled.
- [x] Build's buttons, "Publish" and "Unpublish…" are disabled while a build, publish or unpublish runs for the site, and while a change to the site is being saved.
- [x] The section can be used with the keyboard, the confirmations are alert dialogs with "Cancel" focused, and its fields, buttons and progress have accessible names; on a phone it stacks under Build without scrolling sideways.
- [x] A journey sets the account ID in Settings and a site's target, publishes to a local fake R2, sees "up to date", changes a frame, sees "files to update", publishes again and unpublishes.

## What was built

- **Page:** `sites/publish-panel.tsx`, below Build on the site's page: the "Where to publish" form (Bucket, Address, Save), the state line, progress, "Publish"/"Cancel", "Unpublish…", "View site", the two confirmations and "Open Settings" after messages fixed there. `sites/published-time.ts` formats the time; `forms/issue-for.ts` finds a refused field's message.
- **Shared state:** `use-site-status.ts` (from `build-panel.tsx`) and `use-site-published.ts`; `site-page.tsx` holds both, so Build waits while the site is published or unpublished and Publish while it's built, and each asks the other again when it ends. `useSiteSaver.save` now gives back how the save ended, with a 422's issues.
- **Journey:** `test/e2e/publish-site.e2e.ts`, against a local fake R2 started by `test/e2e/serve.ts` (its own credentials file, `AWS_SHARED_CREDENTIALS_FILE`, and `FILMFILE_R2_ENDPOINT`, read by `readLocalConfig` and given to `R2PublishBucket` by `composeLocal`). The "files to update" step changes the site's title and builds it again, since the bucket is compared with the built site.
- The fake archive answers the four publishing routes, with a scripted bucket and publish progress.

## Not in this task

- The service's work: the routes, uploading and the keys (FF-201).
- Checking the fields in the page as they're typed: the service's rules and words are the only ones.
- Retrying a failed check or publish on its own.
- The account ID and the steps in Cloudflare, which are in Settings (FF-236).
- A folder in the bucket (FF-235), S3 (FF-200) and publishing automatically on a change.

## Notes

- **Routes (FF-201, FF-236):** `PATCH /api/sites/{slug}` with `publish` (`{ bucket, address }`, or `null` to take it away) through the site's saver; `GET /api/sites/{slug}/published` (`stands`, `check`, `publishedAt`, `filesToUpdate`, `filesInBucket`, `publish` progress), polled while a publish runs as the build's status is; `POST` and `DELETE /api/sites/{slug}/publish`; `DELETE /api/sites/{slug}/published`. When the bucket can't be asked, `GET …/published` answers `stands: "unknown"` with the failure's message in `check`, which is what the section shows beside "Check again".
- **Build and publish together:** the section and `build-panel.tsx` (its model) read each other's state through their queries (`['sites', slug, 'status']` and `['sites', slug, 'published']`), so each disables its buttons while the other runs, and each refetches the other when it ends.
- **When it checks:** on opening the page (the rest of the page works meanwhile), after a build, publish, unpublish or saved target, and on "Check again". A check lists the bucket and hashes the built files (FF-201), a second or two for a big site.
- **The time** is formatted by one small function, with its own test, using `Intl.DateTimeFormat` in the computer's time zone: "13 Nov 2026, 14:02".
- **The journey's bucket:** `test/e2e/serve.ts` starts the fake R2 server (`apps/backend/test/support/fake-r2-server.ts`) with a bucket, writes a credentials file with a `[filmfile]` profile and sets `AWS_SHARED_CREDENTIALS_FILE`, and sets a new `FILMFILE_R2_ENDPOINT` to the fake's address (any account ID then goes to the fake). `readLocalConfig` reads it and `composeLocal` gives it to `R2PublishBucket`'s `endpoint`. It's for testing, read only from the environment, never from a request, and documented as such.
- **Tests:** web (the section's states, messages, confirmations and disabled buttons, from the fake archive, which gains the four routes and a bucket's state), a unit test for the time format, a test for `FILMFILE_R2_ENDPOINT` in `readLocalConfig`, and the journey above.
