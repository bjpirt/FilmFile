# FF-182 Preview a site's frames grouped by roll or event

**Status:** to do · **Group:** 13. Sites

## Why

Seeing a site's frames as a visitor will find them, by roll or by event, not as one flat list.

## What

A "Group by: Roll | Event" switch above the grid of matching frames on a site's page splits the grid under a heading for each roll or event, each of which folds away. The grouping comes from the search API, made by the same domain code as the built page, so the preview and the site agree. _(From feedback on the first sites, FF-119 and FF-120.)_

## Acceptance criteria

- [ ] Above the grid, beside the count, a "Group by" switch with "Roll" and "Event", Roll at first; the choice is remembered in the browser, not saved in the site, and changes the grid at once.
- [ ] With "Roll" the grid is split under each roll's number and name and its frame count ("2026-053 Westfjords · 12 frames"), in the order of each roll's first frame in shot order.
- [ ] With "Event" it is split under each event's name, its date and its frame count ("Iceland 2026 · March 2026 · 8 frames"), in the order of each event's first frame; every frame in no event, marked "No event" (FF-173) or never given one, is last under "No event set".
- [ ] A group's count is of its frames on the site, not those excluded ("1 frame"); a group whose frames are all excluded still shows, with "0 frames", so they can be included again.
- [ ] Each heading has a ▸/▾ button (labelled "Fold 2026-053 Westfjords" / "Unfold …") that folds its frames away; all are open when the page opens, and folding isn't remembered.
- [ ] Excluded frames (FF-181) stay greyed in their group, in their place.
- [ ] `POST /api/frames/search` takes `groupBy` (`roll` or `event`) and returns `groups`, each with its heading, detail (an event's date) and frames in shot order, plus the overall count; the groups are made by the same domain function as the built page's (`groupPhotos`), and an API test shows the two give the same headings in the same order.
- [ ] With no matching frames the page says "No frames match" as now, with no headings.

## Not in this task

- "Both" (rolls within events, or the other way): FF-183 decides what "both" means on the built site, and adds it here if it's wanted.
- Saving the preview's grouping in the site, or the built site's own view menu (FF-183).
- Links from a heading to the roll's or event's page in the app.

## Notes

- The switch is independent of the site's "Group by", which FF-183 replaces with a menu on the built site; until then the two can differ.
- `groupPhotos` takes `SitePhoto`s; generalise it over anything with a roll and an event label (or map search results to that shape in the use case), keeping it in `domain/sites/` or moving it to `domain/selections/`.
- Remembered with `localStorage` (wrapped, as other remembered UI choices are).
- Needs FF-181 (the excluded frames and the count's wording); do after it.
- Tests: the domain grouping (shared), the search API with `groupBy`, the site's page (switch, headings, counts, folding, excluded in place) and a step in `sites.e2e.ts` (switch to Event and see "No event set").
