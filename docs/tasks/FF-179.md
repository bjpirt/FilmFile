# FF-179 A site's name is its title, and it has no intro

**Status:** done · **Group:** 13. Sites · **Built in:** 13. Sites

## Why

A simpler site with nothing to type twice and nothing unused.

## What

A site has one "Name", which is also the heading and the browser-tab title of its built page. "Page title" and "Intro" go from the site's page, and `title` and `intro` go from a site's presentation. _(From feedback on the first sites, FF-119 and FF-120; took over FF-180.)_

## Acceptance criteria

- [x] A site's page has "Name" (with "Rename", as now) and no "Page title" or "Intro"; "Group by" and "Captions" stay, in a panel with no heading (its "How it looks" heading removed on review).
- [x] The built page's heading and `<title>` are the site's name exactly as typed, and it has no intro paragraph.
- [x] Renaming a site within its slug ("Iceland" to "ICELAND") makes it "Out of date" until it is built again. A rename to a new slug moves its address and file, so it reads "Not built yet" for the new folder, and a folder already built under the old slug is left in `Sites/`, as FF-119 says. _(Reworded: a rename to a new slug was never going to read "Out of date".)_
- [x] A site's `presentation` is `groupBy` and `captions` only, in its file, the API (`GET`, `POST`, `PATCH`), the OpenAPI spec and the generated types; a site with plain defaults still stores no `presentation`.
- [x] The fake archive and the site's page tests have no title or intro; `build-site.e2e.ts` finds the built page's heading by the site's name, as it already did.

## What was built

- `SitePresentation` is `groupBy` and `captions`; `SiteOptions.title` is the site's name, set in `SiteBuilds`, so the manifest's options change with the name and the up-to-date check sees it. `renderSitePage` writes no intro, and the stylesheet's `.intro` rule is gone.
- The contract's `SitePresentation` (and so the OpenAPI spec and generated types), the site file and the manifest file have no `title` or `intro`. The site file's reader isn't strict, so an older file with them still loads, and they're dropped on its next save.
- A site's page has a panel of "Group by" and "Captions", with no heading.
- On review, the page no longer says "Saving…" and "Saved": changes save quietly, as everywhere else in the app, and only a failure is said. "Build site" is disabled while a change is being saved, so a build never uses the settings before it.
- Tests: the API (a presentation with a title or an intro is refused; the built page's heading and `<title>` are the name; a rename within its slug makes the site out of date), the domain page, the repository and folder contracts, and the site's page.

## Not in this task

- A title different from the name, or any text under the heading: add them back if missed; the layout in FF-183 may bring a description on a card.
- Migrating sites saved before this: none is needed, since the reader ignores the old fields.
