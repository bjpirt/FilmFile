# FF-153 Freeform roll numbers

**Status:** done · **Built in:** 2. Library management

## Why

I can name rolls in the terms I use, rather than having to make every roll number fit one fixed format.

## What

The “Roll number” field on New roll and Edit details accepts any non-empty text up to 100 characters, after trimming surrounding whitespace. The stored number preserves the remaining text exactly. Roll numbers remain unique case-insensitively; numeric suffixes with the same value remain equivalent as in D76, and the rolls list sorts them naturally without regard to case.

The roll-number label is separate from the folder name. The folder label follows D79: ASCII letters, digits and hyphens are kept; each other character becomes `_`; a leading hyphen is prefixed with `_`. New roll folders use the shot year as their `rolls/YYYY/` parent. Once created, a roll folder keeps its parent permanently, even if its number or shot year later changes; changing an existing roll's number renames only its sanitized leaf folder.

## Acceptance criteria

- [x] New roll and Edit details accept any non-empty roll number up to 100 characters after trimming surrounding whitespace, including characters such as `/`, `\`, spaces and non-ASCII text. The exact remaining text is saved and shown as the roll number.
- [x] Creation, editing and “Number rolls…” reject a roll number that is already in use, case-insensitively; numeric suffixes with the same value remain equivalent as in D76. A rejected create or update changes no roll and shows the existing duplicate-number message.
- [x] Rolls sort by their roll numbers using natural, case-insensitive order; numerically equivalent suffixes sort consistently.
- [x] A new roll's folder is `rolls/<shot year>/<safe label>-<ID>/`. Its safe label uses the D79 rule, so separators and other non-ASCII/non-label characters cannot escape the roll folder.
- [x] Changing the number of an existing roll renames only the leaf folder, using the new safe label. Its existing parent year is retained permanently, including when its shot date or number changes.
- [x] The folder ID keeps folders unique when different freeform numbers sanitize to the same label.
- [x] Filed rolls remain uneditable by number; the existing filed-roll behavior is unchanged.
- [x] Tests cover arbitrary labels, trimming and length, sanitization, case-insensitive and numeric-suffix collisions, natural sorting, folder renames, and collisions or failed saves.

## What was built

New roll and Edit details accept trimmed roll-number labels up to 100 characters and keep their original spelling in `roll.json` and API responses. The contract, domain parser, filesystem and holding-area readers all accept the same freeform values. Duplicate checks are case-insensitive and treat equal trailing numeric suffixes as equivalent; roll lists sort naturally without case.

New folders use the shot year as their parent and a D79-safe label plus the roll ID as their leaf. Renumbering sanitizes the new leaf but keeps an existing folder's parent. IDs allow different freeform labels that sanitize alike to use distinct folders. The OpenAPI schema and generated client were updated; tests cover API create/edit, repository contracts, persistence, safe paths and the browser forms.
