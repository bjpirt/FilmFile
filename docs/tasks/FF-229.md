# FF-229 One computer edits at a time

**Status:** to do · **Group:** 17. Sync and backup

## Why

So two computers never both change the library, and there's never anything to merge.

## What

Once sync is set up, a computer edits only while it holds the lock. Without it the library is read-only and says who is editing. "Edit on this computer" brings it up to date and takes the lock. "Done editing here" backs up and hands it back.

## Acceptance criteria

- [ ] With sync set up and the lock held by another computer, every page is read-only: every control that changes the library is disabled. A bar reads "Read-only: MacBook is editing (since 16 Nov 2026, 14:10)."
- [ ] With the lock free, the bar reads "Read-only: no computer is editing." with "Edit on this computer". Pressing it syncs down as needed (FF-228), then takes the lock. The bar goes and the controls are enabled.
- [ ] While this computer holds the lock, the sync panel has "Sync" (backs up, keeps the lock) and "Done editing here" (backs up, then releases the lock and returns to read-only).
- [ ] If two computers press "Edit on this computer" at once, one gets the lock and the other reads "MacBook started editing first."
- [ ] Without the lock the service refuses every write with 423 and "Another computer is editing this library." Reads still work.
- [ ] The first sync of a library (FF-225) takes the lock for that computer.
- [ ] Without sync set up, nothing changes: no lock and no bar.

## Not in this task

- Taking over from a computer that never hands the lock back (FF-230), and backing up when closing (FF-232).

## Notes

- **Decision:** D116. `filmfile/lock.json` (computer name, computer ID, since when) is created with `If-None-Match: *` and removed only by its holder after a successful sync. The lock never expires.
- Whether this computer holds the lock is checked against the bucket when the app opens and before each sync. It is kept in memory in between, so writes don't wait on the network.
- May split into the service refusing writes and the read-only UI if it grows past one review.
- **Tests:** contract (create-if-absent on both bucket adapters), API (423 without the lock, the lock routes), web (the bar's states, controls disabled), and a journey with two services: one edits, the other is read-only, then they swap.
