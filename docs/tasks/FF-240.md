# FF-240 Cancel stops a sync at once

**Status:** to do · **Group:** 17. Sync and backup

## Why

Pressing "Cancel" during a sync seems to do nothing. It only stops new files from starting, and the four uploads under way run to the end, which takes minutes with big scans. Nothing on screen changes until they finish.

## What

"Cancel" answers at once: it becomes "Stopping…", disabled, and the header reads "Stopping…", until the sync has stopped. The service cuts off the uploads under way, so it stops within a second or two. A file cut off part-way never reaches the bucket, and the next sync sends it, carrying on from the rest (FF-239).

## Acceptance criteria

- [ ] Pressing "Cancel", in Settings or the header's panel, changes it straight away to "Stopping…", disabled. The progress line stays as it was, and the header reads "Stopping…", until the sync has stopped.
- [ ] Once it has, Settings and the panel say "Sync stopped. The next sync carries on where this one left off." as a status, not an alert, and the header goes back to the last finished sync. A sync that fails still says "Sync didn't finish. Nothing already backed up was lost. Try again."
- [ ] Cancelling aborts the uploads under way, not only those still to start, so the sync stops within a couple of seconds, whatever the files' sizes.
- [ ] A file whose upload was aborted isn't in the bucket and isn't counted as sent. The next sync sends it.
- [ ] The bucket's sync record and manifest stay as they were.
- [ ] `GET /api/sync` gives the state `stopping` from the moment the cancel is asked until the sync has stopped, so Settings, the panel and a page opened meanwhile all read "Stopping…". It's in the OpenAPI spec.

## Not in this task

- Pausing and resuming: cancel, then sync again, carries on (FF-239).

## Notes

- **Needs first:** FF-239, so that cutting off uploads under way loses nothing.
- **Service:** `LibrarySync` passes the job's abort signal to `putStream`, which the R2 adapter already passes to its request. `SyncProgress.state` gains `'stopping'`, set by `cancel()`.
- **Tests:** API (cancelling while a held upload is under way aborts it; the state is `stopping` until then, then `cancelled`), contract (`putStream` aborted part-way leaves nothing at its key, for the in-memory bucket and the fake R2), web ("Stopping…" in Settings, the panel and the header, the button disabled, and the stopped message).
