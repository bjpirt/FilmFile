# FF-108 Number rolls by date

**Status:** to do · **Group:** 2. Roll numbers · **Was:** U93

## Why

After importing rolls and giving them shot dates, I can put the rolls I'm
browsing in shot order so their numbers tell me the order to file the
negatives.

## What

"Number rolls…" on the rolls page previews new numbers for every unfiled roll
that matches the current Browse filters. In the selected grid or list view,
each old number is struck through beside its proposed number. Applying changes
only those rolls; filed and filtered-out rolls keep their numbers.

## Acceptance criteria

- [ ] "Number rolls…" beside "New roll" previews the rolls matching the
      current Browse filters, not only the cards currently on screen. Group
      by and sort choices do not change which rolls match. With no filters,
      every roll matches.
- [ ] The preview remains in the selected grid or list view. Each eligible
      roll shows its current number struck through and its proposed number
      after it, grouped by shot year and ordered by shot date; equal or
      partial dates sort by their current date-string order, then by current
      roll number.
- [ ] The Browse Years filter, its counts, and "Group by Year" use shot year.
      A roll whose current number is in a different year is filtered and
      grouped by its shot year.
- [ ] Filed rolls keep their numbers and aren't listed in the preview
      (FF-107). A filed roll is an anchor in the year of its current number,
      even if its shot date is in another year.
- [ ] For each shot year, proposed numbers start at 001 if there is no filed
      roll in that number year, or after the highest filed number otherwise.
      Gaps below the highest filed number stay unused. Numbers held by rolls
      outside the active filters stay fixed and are skipped; selected rolls
      are numbered in shot-date order into the available numbers.
- [ ] Applying updates only the previewed, unfiled rolls; all other rolls
      keep their current numbers. Each changed roll's folder is renamed to
      match its new number (FF-151), including when rolls exchange numbers.
- [ ] If the selected rolls already have the proposed numbers, it says
      "The rolls are in order." and changes nothing.
- [ ] If the next available number would exceed 999, Apply is refused for the
      whole batch with 422, changes nothing, and says "There aren’t enough
      roll numbers left in the affected year. Nothing was changed." Support above 999
      is later work (FF-153).
- [ ] Cancel changes nothing. Changing a Browse filter while previewing
      cancels the preview; numbering must be started again for the new set.
      Apply needs no second confirmation.
- [ ] If any roll whose state was considered for the preview changes before
      Apply, the whole batch is refused with 409 and changes nothing. The
      rolls are refreshed and the page says "Some rolls changed since you
      previewed the numbers. Nothing was changed. Cancel and run ‘Number
      rolls…’ again."
- [ ] The batch API refuses with 422 and changes nothing if asked to renumber
      a filed roll; a stale version remains 409.

## Not in this task

- Requiring a shot year through the roll-creation API (FF-158).
- Numbers above 999, and other roll-number patterns (FF-153).

## Notes

- Needs FF-151 (number-and-ID folders), FF-106 (manual number changes),
  FF-107 (filed rolls), and FF-158 (every newly created roll has a shot year).
- Decisions D66, D70, D71, D73–D76. The Browse filter defines the candidate
  set; the API request carries each considered roll's ID and expected version
  in the JSON body, and the proposed number for each selected roll. The
  version is per roll, not an `If-Match` header for the whole request.
- `POST /api/rolls/numbering` validates the complete final state before
  saving: all expected versions, filed status, number uniqueness, and the
  001–999 limit. Expected validation or concurrency failures change nothing.
  Folders are renamed only after validation succeeds.
- Numbers remain `YYYY-NNN` through this task; FF-153 later permits a
  variable-width suffix.
- Tests: repository contract tests for simultaneous renumbering, swaps,
  fixed numbers, filed rolls and stale versions; API tests for batch
  validation and all-or-nothing failures; rolls-page tests for filters,
  preview, cancellation and conflicts; a browser journey that numbers a
  filtered set around filed and filtered-out rolls.
