# FF-166 Choose where downloads are saved in the desktop app

**Status:** done · **Built in:** 12. Exports

## Why

An export saved straight to where the files are wanted (a Lightroom folder, Dropbox, an external drive, a print shop's USB stick), not left in Downloads.

## What

In the desktop app, a download (a quick export's JPEG or zip, FF-165, or any other file the app downloads) asks where to save it, with the computer's own save dialog, starting at the last place used. A browser keeps doing what it does.

## Acceptance criteria

- [x] In the desktop app, downloading a quick export opens the save dialog with the suggested name (`2026-014-12A.jpg`, `2026-014 Westfjords.zip`), starting in the folder last saved to (Downloads the first time).
- [x] Choosing a place saves the file there and remembers its folder; cancelling the dialog cancels the download and the work.
- [x] When it's saved, the app says "Saved to /Users/ben/Pictures/Iceland/2026-014 Westfjords.zip" with a "Show in Finder" button.
- [x] The last folder is remembered by the app, per computer (D52).
- [x] A browser's downloads are unchanged.

## Not in this task

- Saved exports (FF-117), which are always made in `Exports/<slug>/` in the FilmFile folder.
- A folder chosen once and exported to again without asking.

## Notes

- D95. The desktop app handles the window's `will-download` event and shows its own dialog (`dialog.showSaveDialog`), so the service is never told a path: it writes nothing outside its own folder (CLAUDE.md, the `security-rules` skill), and the page can't ask the app to save anywhere.
- Tests: the download handler (the suggested name, the remembered folder, a cancelled dialog) as a unit test over fakes, and a desktop journey that answers the save dialog, as the others do.

## What was built

`apps/desktop/src/handle-download.ts` (no Electron in it, so it's unit tested over a fake download) handles the session's `will-download`: it sets the save dialog to start in the folder last saved to, or Downloads the first time, suggesting the name the service gave, and tells `main.ts` once the file is saved. `main.ts` then remembers the folder (`downloadFolder` in the app's `settings.json`, kept beside `folder` by the new `updateSettings`) and says "Saved to …" with "Show in Finder" ("Show in Folder" off a Mac). Cancelling the dialog cancels the download and says nothing. The service is never told a path. The desktop journey's dialog stand-in (`test/e2e/support/desktop-dialogs.ts`) answers a download with `{ "save": path }` or `{ "cancel": true }`, since the save dialog itself is native and can't be driven.
