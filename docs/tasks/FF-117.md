# FF-117 Build an export

**Status:** to do · **Group:** 12. Exports · **Was:** U95

## Why

The photographs I've chosen are there as ordinary JPEGs in a folder, made the way I want, for anything else to use.

## What

"Build export" on an export's page (FF-116) writes a JPEG of each of its frames into `Exports/<slug>/`, from the version shown, turned as it's shown, at the size, quality, layout and names the export says. Always worked out from the archive as it is, and only what changed is made again: the page says whether the export is up to date. An export can optionally keep itself up to date.

## Acceptance criteria

The files:

- [ ] An export has "Size" (Full size, or a longest edge in pixels, e.g. 2048 px), "Format" (JPEG) with "Quality" (1 to 100, 90 at first), "Metadata" (as in FF-118), "Layout" (Flat, A folder per roll, or Year then roll) and "File names" (a pattern of `{roll}`, `{frame}`, `{title}`, `{year}` and `{original}`, `{roll}-{frame}` at first), saved in the export; the same choices, layout and names as the zip of selected frames (FF-167).
- [ ] "Build export" writes `Exports/iceland-2048/2026-014 Westfjords/2026-014-12A.jpg` for each frame on the export (with the layout and names chosen), and says "Export built in Exports/iceland-2048: 24 photos (3 made, 21 unchanged)."
- [ ] Each is made from the frame's version shown (FF-103), turned as the frame view shows it; a raw version shown is made from the largest preview it carries; a frame with no version is skipped and listed.
- [ ] Names that would be the same get a `-2`, `-3` after them; a name has only safe characters, as folder names do (D79).

Up to date, and made again:

- [ ] `Exports/<slug>/export.json` records each file, the frame it's from and what it's made from (the version's own hash, its turn, and the size, format, quality and metadata choice); the export's page says "Not built yet", "Up to date", or "Out of date: 3 added, 1 removed, 2 changed" by comparing it with the frames now on the export.
- [ ] Building an export that's up to date changes nothing: no file is rewritten.
- [ ] A frame rated down, hidden, rotated, given another version to show, deleted, or moved out of what the rules match makes the export out of date, as changing its size, quality, metadata, layout or names does.
- [ ] Building makes only the files whose inputs changed, removes files FilmFile made that are no longer on the export, and moves or renames a file, without making it again, when only the layout or its name changed; files in the folder that FilmFile didn't make are left alone.
- [ ] A build writes each file whole before it appears (a temporary name, then renamed), so a folder being read by another program never sees half a file; a failed or cancelled build leaves what was already there.
- [ ] While it runs the page shows "Making photos: 12 of 40" and a "Cancel" button; a frame that can't be made is skipped and listed with why, and the rest go on.
- [ ] If `Exports/<slug>/` holds something with no `export.json`, building says so and changes nothing.

Keeping it up to date:

- [ ] An export has "Keep up to date automatically", off at first, saved with it: when on, the service refreshes it within moments of a frame, version or the export itself changing, and on starting, and the page says "Updated 2 minutes ago".

## Not in this task

- Formats other than JPEG, sharpening, colour space and watermarks.
- A destination outside `Exports/`.

## Notes

- Replaces D60 (D94): `Exports/` is no longer one folder of marked frames but one folder per export. The out-of-date state and what's made again are the same mechanism as a site's (FF-120): the rendering, the manifest of inputs and the comparison are shared code.
- The rendering (the version shown, turned as it's shown, resized, with the metadata chosen) is the code made for FF-165 and FF-118, which the zip of selected frames (FF-167) and building a site (FF-120) use too.
- API: `POST /api/exports/{slug}/build` (progress and cancel), `GET /api/exports/{slug}/status`; the recipe is part of the export's record (FF-116's `PATCH`).
- Automatic refresh needs the service to see changes: through the use cases that change frames and versions, not by watching the library's files.
- Journey: make an export of rated frames, build it, find the files in `Exports/`, rate one more and see it out of date.
