# FF-103 Choose the version shown

**Status:** to do · **Group:** 6. Versions and scans · **Was:** U62

## Why

A frame's first version, the lab's scan, isn't always the one I want to see once I have better.

## What

In the versions column (U61), each thumbnail has a star at its top left, filled on the version shown everywhere (`defaultVersion`, D15, D46) and outlined on the others. Clicking an outlined star makes that version the one shown on contact sheets, filmstrips, event pages and in the frame view. The star replaces the "Shown everywhere" text label under the thumbnail. The frame view's large image stays on the version being looked at.

## Acceptance criteria

- [ ] Each version in the versions column has a star at its top left, always visible: filled on the version shown everywhere, outlined on the others. The star replaces the "Shown everywhere" label under the thumbnail.
- [ ] The star is a button named "Show this everywhere" on the others, with the same hover text, and "Shown everywhere" on the filled one; it's in the Tab order and works by touch as well as by mouse.
- [ ] Clicking another version's star makes that version the one shown on contact sheets, filmstrips, event pages and when the frame view next opens, saved with `PATCH /api/rolls/{rollId}/frames/{frameId}` (`defaultVersion`) and `If-Match`.
- [ ] Clicking a star doesn't change which version the large image shows; clicking the thumbnail still does.
- [ ] Clicking the first version's star goes back to the first: the frame records no choice (`defaultVersion: null`), so "the first" still means the first if it's later deleted (D46).
- [ ] Clicking the star of the version already shown does nothing, so one version is always shown.
- [ ] The star moves at once and is saved in the background, queued with the frame view's other saves so they never clash; the contact sheet, filmstrip and event pages show the new version straight away.
- [ ] A save refused because the roll changed (409) puts the star back and shows "This roll changed since you opened it. Reload the page."; any other failure puts it back and shows "Couldn't save it. Is the service running?".
- [ ] Deleting the version shown (U28b) puts the first back (`defaultVersion` cleared), and the star is filled on it. (Already built; this is its regression test.)
- [ ] A frame with one version shows no versions column, so no star.
- [ ] In the "Catalogue a roll" journey: a frame given a second version, then that version's star chosen, shows the second version's picture on the roll's contact sheet after a reload.

## Not in this task

- Showing the newest Final by itself (FF-135), which will treat a chosen version as overriding it.
- A "Show this everywhere" entry in the "⋯" menu: the star replaces it (U28b's menu keeps "Mark as…" and "Delete version…").
- Starring from the contact sheet or the filmstrip; it's done in the frame view only.

## Notes

- Uses the frame's existing `defaultVersion` (D15, D46): the service's `UpdateFrame` already accepts it, checks the version is the frame's own, and `DeleteVersion` already clears it. No API or data change.
- Needs U61 (the versions column), U34 (adding versions) and U28b (deleting one).
- The star sits beside the thumbnail button, over its top left corner (a button can't be inside the thumbnail's button), like the "⋯" menu at its other corner.
- Saving reuses the frame view's `useSaveFrame`, gaining an at-once update of the roll's cached frame like FF-149's `useRateFrame`.
- Tests: frame view tests for the stars, the names and the Tab order, choosing another version, choosing the first (null), the shown version's star doing nothing, the 409 and another failure, the large image staying put, the filmstrip and contact sheet following, and a frame with one version; an API test that `defaultVersion` is saved and cleared; the "Catalogue a roll" journey extended as above.
