# FF-216 An event's reads and writes in one place

**Status:** to do · **Group:** 16. Internal improvements

## Why

The list of events is defined in three places, an event in two (under different keys), and the events pages make their writes directly. `use-events.ts` already holds the list; the rest of the feature should follow it.

## What

`events/use-events.ts` holds every events query key and read, and `events/event-changes.ts` their writes. The events pages, the event chooser and the selection editor use them. Nothing a person sees changes. _(Recommendation R7 of the architecture review, for events. The review advises doing this when feature work next touches events, not up front.)_

## Acceptance criteria

- [ ] `apps/web/src/events/use-events.ts` exports the keys as functions (`eventsKey`, `eventKey(slug)`) and the one definition of each query: the list (`useEvents`, as now), an event's frames (`useEventFrames`'s query, now in `event-frames.ts`) and an event with its version for editing.
- [ ] The list of events is defined only there: `events-page.tsx` and `selections/use-rule-options.ts` use it (the latter through an options object for `useQueries`).
- [ ] An event is read under one key, or two keys with a comment saying why they must differ (today `['events', slug]` in `event-frames.ts` and `['events', slug, 'with-version']` in `event-editor.tsx`).
- [ ] `apps/web/src/events/event-changes.ts` has one function each for: make an event (`events-page.tsx` and `choose-event.ts`) and save an event (`event-editor.tsx`), returning a small union of outcomes and refreshing what they refresh now.
- [ ] `events-page.test.tsx`, `event-page.test.tsx`, `frame-events.test.ts` and the Playwright journeys pass unchanged.
- [ ] Each new write function has a test for each of its outcomes.

## Not in this task

- The list of rolls the events pages read: FF-212 defines it once.
- Changing what the event pages show.
