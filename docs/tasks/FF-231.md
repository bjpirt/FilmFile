# FF-231 When both computers have changed

**Status:** to do · **Group:** 17. Sync and backup

## Why

After a takeover, the computer that lost the lock may have changes it never backed up. The person chooses which side to keep, and nothing is lost either way.

## What

When this computer and the bucket have both changed since this computer's last sync, "Sync" explains what happened and offers to keep this computer's changes, take the bucket's, or cancel. The losing side's changed files are copied to `Set aside/<date>/` in the FilmFile folder.

## Acceptance criteria

- [ ] "Sync" with both sides changed asks: "MacBook synced on 16 Nov 2026, 15:02, after this computer's last sync on 16 Nov 2026, 11:40, and both have changes." It lists the rolls changed on each side, with "Keep this computer's", "Take the bucket's" and "Cancel".
- [ ] "Take the bucket's" copies this computer's changed and new files to `Set aside/2026-11-16 1502/`, keeping their library paths. It then syncs down as in FF-228.
- [ ] "Keep this computer's" downloads the bucket's versions of the files that differ to `Set aside/…`. It then syncs up, and only then takes the lock (if free).
- [ ] "Keep this computer's" is offered only when the lock is free or held by this computer. Otherwise it reads "iMac is editing. Take the bucket's, or ask iMac to finish first."
- [ ] Afterwards the panel says "3 files set aside in Set aside/2026-11-16 1502." with "Show in Finder" in the desktop app.
- [ ] `Set aside/` is never synced or backed up, and FilmFile never deletes it.

## Notes

- **Decision:** D116. Image files never clash (write-once), so in practice the differences are JSON files and new versions.
- **Tests:** unit (which files go aside on each choice), API, web (the choice and its messages), and a journey continuing FF-230's: the taken-over computer syncs and takes the bucket's.
