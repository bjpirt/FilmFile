# FF-105 The FilmFile folder

**Status:** to do · **Group:** 2. The FilmFile folder · **Was:** U89

## Why

One place to find, back up and move, with the library kept apart from what's made from it, and one way to say where it is: chosen with a folder chooser in the app, or by `FILMFILE_FOLDER` when running as a web service.

## What

FilmFile keeps everything in one **FilmFile folder** (D57), and the library is its `Library/` (D63). The service needs `FILMFILE_FOLDER`, and `FILMFILE_ARCHIVE` goes. The desktop app asks for the folder with the system's folder chooser, replacing U83's question for an archive. Only a valid FilmFile folder opens: an empty folder (which becomes a new one) or one with a `Library/`. Replaces U73's NegPy folder setting. Moving the archive's settings file up to the folder, the API's rename and showing the folder in Settings are FF-150. *(Narrowed when FF-150 was split from it.)*

## Acceptance criteria

The service:

- [ ] The service needs `FILMFILE_FOLDER`, the absolute path of a FilmFile folder, and stops with "Set FILMFILE_FOLDER to your FilmFile folder." without it; `FILMFILE_ARCHIVE` is no longer read.
- [ ] Its library is the folder's `Library/`; the cache is where it was (the OS cache folder, or `FILMFILE_CACHE`), never in the folder.
- [ ] On starting, a folder with nothing but hidden files in it gets a `Library/` made, and the service runs; a folder with a `Library/` runs as it is; any other folder, or one that isn't there, stops it with a message saying what's wrong. Nothing else is made in the folder.
- [ ] An archive folder chosen as the FilmFile folder (it has `archive.json` directly in it) is refused as any other folder is.
- [ ] No API route takes a folder path (D64).

The desktop app:

- [ ] On first launch, with no folder remembered, a message says "FilmFile keeps your library, and everything made from it, in one folder. Choose where." with Quit and Choose Folder….
- [ ] Choose Folder… opens the system's folder chooser titled "Where should FilmFile keep its files?", starting at `~/Pictures/FilmFile` (or `~/Pictures` when that isn't there), with New Folder and "Use This Folder"; cancelling goes back to the message.
- [ ] Choosing an empty folder opens on "Set up your archive" for a new library, made as `Library/` in it by the service.
- [ ] Choosing a folder with a `Library/` opens it, even one whose library was never set up, which asks to set it up.
- [ ] Choosing any other folder is refused ("That isn't a FilmFile folder.", saying it has other files in it or no library, and to choose your FilmFile folder or an empty one) and asks again; an archive folder chosen directly is refused the same way.
- [ ] The choice is remembered on this computer (D52, as `folder` in the app's `settings.json`) and later launches open it without asking; the old `archive` setting from U83 is ignored.
- [ ] A remembered folder that has gone missing says "FilmFile can't find your folder. It was at `<path>`. If it's on a drive that isn't connected, connect it and try again." with Try Again, Choose Another… and Quit. One that's there but no longer valid is refused as choosing it would be, offering Choose Another… and Quit.
- [ ] `FILMFILE_FOLDER` in the app's own environment is used in place of asking, for development and the journeys, and isn't remembered.
- [ ] File › "Open FilmFile Folder…" (⌘O) replaces "Open Archive…": it asks as above, opens the folder in a new window on a new service, closes the old, and remembers it.
- [ ] File › "Show FilmFile Folder in Finder" opens the folder in Finder.

Development:

- [ ] `pnpm start`, `pnpm start:dev`, `pnpm dev`, the README's example, the browser journeys' servers, the desktop journeys and the packaged app's journey all use `FILMFILE_FOLDER`; the development folder moves from `.dev-archive/` to `.dev-folder/`.
- [ ] The first-run journey still sets the archive up on a new, empty folder, and every browser journey runs as before.

## Not in this task

- Opening, converting or moving an archive that isn't in a FilmFile folder.
- Making `Exports/`, `Sites/`, `Editors/` or `Browse/`: each is made by the task that first needs it (FF-117, FF-120, FF-112, FF-111).
- The settings file at the folder's top level, the API's rename to settings, and showing the folder's path in Settings (FF-150).
- Changing the folder from the Settings page, which would need a bridge into the app (D54's "no preload" stands).
- Putting one of the folders somewhere else (on a NAS, say).

## Notes

- Decisions D63 (the folder, `FILMFILE_FOLDER`, what's valid) and D64 (a path is never set through the API).
- The archive's own details stay in `Library/archive.json` and `/api/archive` until FF-150.
- Caches stay in the OS cache folder, never in the FilmFile folder. Backup and sync (design section 10) cover `Library/` and, from FF-150, `settings.json`.
- The service checks the folder, because a browser or development run has no dialogs; the desktop app checks first, with the same rule, only to show its dialogs.
- Journeys, all in the desktop app's: first launch (the message, the chooser, a refused folder of other files, an archive folder refused, an empty folder making `Library/`, the choice remembered), Open FilmFile Folder…, a folder gone missing, and Show FilmFile Folder in Finder. The test helper (`desktop-dialogs.ts`) also answers the first-launch message and records the path the app asks the system to open. The final check runs everything (`check.sh --desktop`).
- Backend tests: reading `FILMFILE_FOLDER` and the three folder cases.
