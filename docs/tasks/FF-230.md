# FF-230 Take over editing

**Status:** to do · **Group:** 17. Sync and backup

## Why

A computer that crashed, was wiped or was left asleep somewhere shouldn't stop the library being edited anywhere else.

## What

When another computer holds the lock, the read-only bar offers "Take over editing", after a warning. The lock never expires, so this is the only way to take it from a computer that doesn't hand it back.

## Acceptance criteria

- [ ] The read-only bar has "Take over editing". It asks: "Take over from MacBook? It has been editing since 14 Nov 2026, 09:12. Changes it hasn't backed up will be set aside when it next syncs." with "Take over" and "Cancel".
- [ ] "Take over" syncs down, then takes the lock. The other computer's lock is replaced only if it's still the one that was shown. If it changed meanwhile, it reads "The lock changed while you were deciding." and shows the bar again.
- [ ] The computer that lost the lock finds out when it next opens or syncs. Its bar reads "Read-only: this computer was taken over by iMac on 16 Nov 2026, 10:30." Its writes are refused from then on.
- [ ] A sync from the computer that lost the lock can't change the bucket: its sync record write fails, and it goes to the both-changed choice (FF-231) if it has changes.

## Notes

- The takeover replaces `lock.json` with `If-Match` on the ETag read.
- **Tests:** contract (conditional replace), API, web (the warning, the lost-lock bar), and a journey with two services where one takes over from the other.
