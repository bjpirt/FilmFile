# FF-154 Import many rolls at once

**Status:** done · **Built in:** 7. Roll numbering and filing

## Why

A pile of lab downloads, one folder per roll, shouldn't mean making a roll and dropping its scans by hand, over and over. They're brought in together, numbered automatically, and dated and put in order afterwards (FF-108).

## What

"Bulk import rolls…" on the rolls page, beside "New roll", opens a Bulk import rolls page. Choose or drop a folder whose subfolders each hold one roll's scans; each subfolder with scans becomes a roll, named after its folder, dated from its name where it has a date and numbered from the roll number pattern in Settings (D88), previewed first ("roll A: 36 frames → 2026-016") with each roll's date editable. Importing creates each roll and adds its scans in file name order, with progress and a Cancel, and ends with a summary.

## Acceptance criteria

Choosing the folder:

- [x] The rolls page has an "Bulk import rolls…" link beside "New roll", opening a "Bulk import rolls" page (`/rolls/import`) with a drop zone, "Drop a folder of roll folders, or several roll folders, here", and a "Choose folder" button (a folder picker, which also works in the desktop app).
- [x] One folder dropped or chosen, or several dropped together: a folder that holds JPEGs (`.jpg` or `.jpeg`, not dot-files such as `._12340001.jpg`) is a roll, and one that holds none is a folder of rolls, each of its direct subfolders that holds a JPEG being a roll. Rolls are in natural name order (so "roll 2" comes before "roll 10"). Deeper folders, files dropped on their own and other kinds of file are ignored. (The folder picker takes one folder.)
- [x] A folder with no JPEGs is listed as "Skipped: thumbs (no scans)" and not imported; when nothing has scans the page says "There are no roll folders with scans in it."

The preview:

- [x] The rolls are a table with the headings Folder, Frames, Date shot and Number, rules between the rows and alternating row backgrounds; each roll is a row: a ticked checkbox ("Import roll A"), the folder's name, its frame count, its date as editable Year, Month and Day fields in one line (named for screen readers, with the column heading above), and the number it will get, e.g. "roll A", 36, 2026, 2026-016. "Import N rolls" imports the ticked rows and is disabled when none are ticked.
- [x] A roll's name is its folder's name (trimmed, at most 100 characters); the roll has no other details (camera, film, lens, event, notes), set later.
- [x] A roll's date is read from its folder's name: the first whole year of 19nn or 20nn (not part of a longer number, so `12340001` has none); a month and day too when the name gives them (`2024-08-12 Iceland`, `20240812`, `2024-08`). With no year in the name, the year is this year. Month and day are otherwise empty. Every part can be changed in the row, and the numbers follow.
- [x] The numbers come from the pattern in Settings (D88): for the ticked rows in natural name order, each takes the next free number for its date (and event) group, after the highest existing matching number, never reusing gaps and skipping numbers that rolls already have or earlier rows will. A number's date parts come from the row's date, so a roll dated 2019 gets a 2019 number. Unticking a row, or editing a date, updates them.
- [x] Where the pattern uses a month, day or event the roll doesn't have, the number has "MM", "DD" or "event" in its place (e.g. `event-2026MM-01`), and the page says "Numbers with MM, DD or event need those details: set them on each roll, then choose Re-number rolls…".

Importing:

- [x] Importing makes each ticked roll one after another, in order, with its number, name and date (year, and month and day when given, as `shot`), and no event even when the pattern uses one, then adds its scans one at a time in file name order as frames 1, 2, 3…, as New roll's scans are (so a lab that scanned from the tail is fixed by renumbering).
- [x] While it runs the page shows "Importing roll 3 of 12: frame 10 of 36" and a "Cancel" button. Cancel stops after the file in progress; everything imported so far stays, and the summary says what was left.
- [x] A scan the service refuses, or a roll that can't be made, doesn't stop the import: a failed scan is skipped and listed with its reason; a roll whose number was taken in the meantime is given the next free number and tried again; any other roll that can't be made is skipped, with its scans, and listed.
- [x] It ends with a summary on the same page: "Imported 12 rolls, 430 frames." (and "Cancelled: 2 rolls not imported." when stopped), then a table with a row to each folder in order: Number (a link to the roll), Name, Date, Frames and a Status that says "Added", or what needs a look: scans not added and why, a number with MM, DD or event ("Set its date or event, then choose Re-number rolls…"), "Couldn't be made" and why, or "Not imported (cancelled)"; and a link to "All rolls".
- [x] Importing the same folder again makes new rolls: folders already imported aren't detected.
- [x] Creating or editing a roll no longer refuses one that lacks a month, day or event the pattern uses (D89); saving the pattern is still refused until every roll has them, and "Re-number rolls…" still says "A roll needs a shot month before it can be numbered with your roll number pattern." (or an event) and changes nothing.

## What was built

The rolls page has an "Bulk import rolls…" link beside "New roll" to `/rolls/import` (`rolls/import-rolls-page.tsx`). `import-folders.ts` finds the roll folders in a dropped folder (`foldersFromDrop`, reading two levels through the drop's entries) or a picked one (`foldersFromPicker`, from each file's `webkitRelativePath`); `folder-name-date.ts` reads a year, month and day from a folder's name; `import-plan.ts` makes the preview rows (each dated by its name, else this year) and numbers the ticked ones in order with `suggestImportedNumber`, which falls back to "MM", "DD" or "event" in the number (`renderRollNumber`'s `placeholder` option) for what a roll lacks. `import-rolls.ts` (`importRolls`) makes each roll with `POST /api/rolls` (number, name, shot), retrying a taken number with the next free one, then adds its scans with `uploadScans`, which gained a `stop` check and a `notTried` count for Cancel. D89: `CreateRoll` and `UpdateRoll` no longer take the settings or check the pattern (`roll-number-pattern-needs.ts` is gone); saving a pattern and "Re-number rolls…" still do. `import-summary.tsx` shows the summary as a table with a status column. Folders dropped together are each a roll, so a single roll folder can be dropped too.

Tests: folder-name dates, folder finding (drop and picker), the plan and the placeholder numbers, the Bulk import rolls page (preview, dates, edits, skipped, scans in the folder, placeholders, import, a taken number, a refused scan, a roll that can't be made, cancel), the rolls page link, an API test that a roll can be made and edited without what the pattern uses, and the "Bulk import rolls" journey (choose a folder of two roll folders, preview, import, find them after a reload).

## Not in this task

- Detecting folders already imported, or skipping them (importing twice makes duplicates, deleted by hand).
- Parallel uploads, retries and resuming (not planned).
- Camera, film stock, lens, event, notes or an editable name or number on each row; set on each roll afterwards, and renumbered with "Re-number rolls…" (FF-108).
- Raw scans or other kinds of file: only lab-style JPEGs, as New roll's scans.
- Rolls nested deeper than a folder's subfolders.
- A service route for importing: the page makes the rolls and uploads their scans with the existing API.

## Notes

- Uses `POST /api/rolls` (with `roll`, `name`, `shot`), then each scan as New roll does (`uploadScans`); no new route, data or API change. The service's own default number is unused here: the page works the numbers out from the pattern (D88) and an `AlreadyExists` (409 from a taken number) is retried with the next free one.
- The rolls come from the folder chosen's entries: dropped folders through `webkitGetAsEntry` (the existing `droppedFiles` reads one level, so this reads two) and the picker's `webkitRelativePath`.
- The shared pattern code (`rolls/roll-number-pattern.ts`) gains a rendering that puts "MM", "DD" or "event" in for what's missing, used for the preview's numbers and the import; counters group by the rendered text, so a batch of placeholder rolls counts up together and a later import skips what's taken.
- D89 removes `rollMeetsPattern` from `CreateRoll` and `UpdateRoll` (`roll-number-pattern-needs.ts` and its tests), keeping `UpdateSettings`' check; FF-159's criteria and D88 are updated to match. The New roll page keeps its own prompt ("Add a shot month: your roll number pattern uses it.").
- Depends on FF-152, FF-153 and FF-159 (pattern numbers), FF-158 (a shot year is needed to create a roll).
- Decisions D89 (create and edit don't enforce the pattern) and D90 (what an import does).
- Tests: page tests for choosing and dropping a folder, the rolls found and skipped, names, dates read from names (year, month, day, none), numbers from the pattern (and placeholders), editing a date, unticking, progress, cancelling, a failed scan, a number taken in between, and the summary; use case and API tests that `CreateRoll` and `UpdateRoll` accept a roll without the month, day or event a pattern uses; the rule's tests for placeholders. A new "Bulk import rolls" journey: choose a folder of two roll folders, see the preview, import, find both rolls with their scans and numbers after a reload.
