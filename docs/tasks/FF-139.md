# FF-139 Windows and Linux

**Status:** later · **Group:** 10. Desktop app · **Was:** U87

## What

The app built and tested for Windows and Linux too, with their own installers.

## Acceptance criteria

Written when the task is planned into a group.

## Notes

What it would take, from looking at the code (the service and UI are already portable: CI verifies them on Ubuntu and macOS, sharp ships a prebuilt binary per platform, and Electron 45 runs on all three):

- **The packaging script** (`apps/desktop/scripts/package.ts`) is fixed to `darwin`/`arm64` and makes a `.app` and a `.dmg` with the Mac-only `ditto` and `hdiutil`. It needs a `platform` and `arch`, the app path and the fuses flipped on that platform's executable (`resetAdHocDarwinSignature` is Mac only), and an artifact per platform: a zip or AppImage for Linux, a zip or a Squirrel installer for Windows.
- **sharp's native files:** pnpm installs only the host platform's, and the script copies sharp's packages in by hand (`copyPackage`), so another platform's app would ship the wrong binary (see FF-161). Linux has glibc and musl variants.
- **Icons:** `apps/desktop/build/` has only `icon.icns`; Windows needs an `.ico` and Linux a PNG.
- **Platform details:** the cache folder in `apps/backend/src/composition/read-local-config.ts` is `~/.cache` on anything but a Mac, so Windows needs `%LOCALAPPDATA%`; the menu says "Show FilmFile Folder in Finder" (`apps/desktop/src/app-menu.ts`), which needs "Explorer" and "File Manager"; File › Quit and the other menus follow each platform's convention.
- **Windows paths:** a Windows verify job will find path bugs in tests and code (separators, the 260-character path limit for deep library paths). Folder names are already safe on Windows: labels keep only letters, digits and hyphens, and the ID suffix keeps a roll called "CON" from being a reserved name. `roll.json` already stores version paths with `/`.
- **Links:** the NegPy folder (FF-112) needs copies where symlinks aren't allowed (Windows without Developer Mode), as FF-112 already notes; read-only originals (FF-109) should behave the same on all three.
- **CI:** add Windows (and an Ubuntu `desktop-app` job, with a virtual display for Electron) to the verify and packaged-app jobs.
- **Signing and updates** are separate (FF-137, FF-138): unsigned builds show Gatekeeper and SmartScreen warnings, and a Windows signing certificate costs money.
- Sizes: Linux 1–2 days (CI already runs on Ubuntu, so it's the cheapest way to find portability problems); Windows 2–4 days.
