# FF-101 One event per frame

**Status:** to do · **Group:** 1. Multi-version frames, finished off · **Was:** U72

## Why

A frame belongs to at most one event of its own. A singular event keeps its details unambiguous and lets roll grouping and event pages place each frame consistently.

## What

Represent a frame's own event as one optional slug, like a roll's event (D50). A frame event overrides its roll's event; when the frame has no own event, it uses the roll's. Use `event` consistently in `roll.json`, the domain model, API and web app. Keep the existing single-select control and bulk “Set → Event…” workflow.

## Acceptance criteria

- [ ] `roll.json` stores a frame's own event as optional `event: <slug>`; it has no `events` array. The frame API response exposes `event` as a slug or `null`.
- [ ] `GET /api/rolls/{rollId}/frames/{frameId}/details` returns at most one resolved `event` with its source; if neither the frame nor its roll has an event, it omits `event`.
- [ ] `PATCH /api/rolls/{rollId}/frames/{frameId}` and bulk `PATCH /api/rolls/{rollId}/frames` accept an optional `event` slug. Omitting it leaves the frame unchanged; `null` clears its own event so it uses its roll's event.
- [ ] An unknown event slug is a 422 validation failure on `event`. A stale `If-Match` is a 409 and changes no frames; a bulk update with an invalid event changes none.
- [ ] The frame details panel uses the singular label “Event”. Choosing an event sets the frame's own event; clearing it shows the roll's event again.
- [ ] Bulk edit's “Set → Event…” sets one event on every selected frame. Clearing the selection's event removes each frame's own event and restores inheritance from its roll.
- [ ] An event page includes a frame under its own event when set, otherwise under its roll's event; a frame is not listed under both. The existing event page and roll grouping remain correct.
- [ ] Pre-release `roll.json` `events` arrays are not migrated. The reader ignores that field; it is not copied to the new `event` field, and a later normal save writes only the singular shape.
- [ ] The “Bulk edit” and “Organise by event” browser journeys pass without adding new UI controls.

## Notes

- Decisions D50 and D84. D50 sets the at-most-one event rule; D84 chooses singular `event` across frame persistence, API and resolved details, and declines compatibility with pre-release arrays.
- In the current implementation `Frame.events`, frame DTOs, PATCH bodies, and resolved details use arrays. Replace those with a nullable singular event for frame assignments and a singular sourced event in frame details.
- The roll's own `event` remains a nullable slug. Inherited frame membership uses the frame's own event when present, otherwise the roll's event.
- Tests: persistence conversion/serialization, domain/use-case validation, frame API DTOs and PATCH, bulk updates, details resolution, and the existing “Bulk edit” and “Organise by event” journeys. FF-102 depends on this contract.
