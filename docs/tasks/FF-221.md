# FF-221 Parse fields that may be left out with one helper

**Status:** to do · **Group:** 16. Internal improvements

## Why

The use cases that create and update rolls and frames repeat the same five lines for every field that may be left out or cleared, about 20 times in all. `UpdateFrame` is 166 lines, most of it this, and the field that matters in each block is hard to see.

## What

A helper, `whenGiven(value, parse)`, parses a value that was given and passes one left out (`undefined`) or cleared (`null`) through, with an async twin, `whenGivenAsync`, for the lookups that check a camera, lens, film stock or event is in the archive. The use cases call them, keeping their early returns. Nothing changes in behaviour. _(Recommendation R9c of the architecture review. The review says do it last of the R9 tasks, and stop if the types fight back.)_

## Acceptance criteria

- [ ] `apps/backend/src/application/use-cases/rolls/when-given.ts` (beside `text-or-null.ts`) exports:
  ```ts
  /** Parses a value that was given; one left out (undefined) or cleared (null) passes through. */
  export function whenGiven<T, U, E>(
    value: T | null | undefined,
    parse: (given: T) => Result<U, E>,
  ): Result<U | null | undefined, E>;
  ```
  and `whenGivenAsync`, the same with `parse` returning a `Promise`.
- [ ] Unit tests: left out, cleared, given and parsed, given and refused, for both.
- [ ] `UpdateRoll`, `UpdateFrame`, `UpdateFrames` and `CreateRoll` use them for every field parsed this way, and keep each `if (!x.ok) { return x; }`.
- [ ] `UpdateFrame`'s and `UpdateFrames`' `event`, which also accepts `false` (no event), handle `false` at the call site, not in the helper.
- [ ] No type assertion (`as`) and no `!` in the helper or its callers. If the helper can't be written without one, the task stops there: nothing is changed, and the task says why.
- [ ] All tests pass unchanged.

## Not in this task

- Hiding the early returns in a combinator or with exceptions: they're the style CLAUDE.md asks for.
- The create and update use cases for anything other than rolls and frames.
