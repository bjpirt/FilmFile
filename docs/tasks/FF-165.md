# FF-165 Export a frame

**Status:** to do · **Group:** 12. Exports

## Why

Sometimes I just want one photograph as a file, once, to send to someone or print, without making and keeping an export for it.

## What

An "Export" button in the frame view opens a dialog with a size and quality; the frame is made as a JPEG and downloaded the normal browser way. Nothing is saved but the choices last used. This is the first use of the image rendering that later exports and sites share.

## Acceptance criteria

- [ ] The frame view's bar has an "Export" button, beside the scan mark and rotate buttons, opening the dialog "Export frame 12A".
- [ ] The dialog has "Size" (Full size, or a longest edge in pixels, 2048 px at first) and "Quality" (1 to 100, 90 at first), and "Export" and "Cancel".
- [ ] The last size and quality chosen are remembered in the browser and are what the dialog starts with.
- [ ] "Export" downloads a JPEG named for the frame (`2026-014-12A.jpg`; `2026-014-frame.jpg` for a frame with no number), made from the frame's version shown (FF-103), turned as the frame view shows it, at the size and quality chosen.
- [ ] A raw version shown is made from the largest preview it carries; a frame with no version says "This frame has no scan to export." in the dialog and makes nothing.
- [ ] The file carries only the author and copyright (the archive's or the roll's) until FF-118 gives the choice; no location is ever written.
- [ ] A failure before the download starts says what went wrong, without internals.

## Not in this task

- The Metadata choice (FF-118), exporting several frames (FF-167), and saved exports (FF-116, FF-117).
- Choosing where the file is saved: that's the browser's (it asks, or saves to Downloads), or in the desktop app FF-166.

## Notes

- D95. API: `POST /api/exports/quick` with the frames (roll and frame IDs) and the recipe checks them and gives a single-use download address; `GET` on it streams the file with a `Content-Disposition` filename. The page follows the address as an ordinary download (no blob held in memory), and the service writes nothing to disk. FF-167 sends several frames the same way.
- The rendering (the version shown, turned as it's shown, resized, quality, metadata) is one piece of code in the service that FF-167, FF-117 and building a site (FF-120) all use.
- The remembered choices are a per-viewer convenience in the browser's storage, not a saved record.
- Tests: the rendering (size, quality, the turn, a raw's preview, the author and copyright written), the use case and API (a frame with no version, a bad request, the single-use address), the dialog, and a journey: open a frame, export it and find the JPEG.
