# FF-121 Publish a site

**Status:** later · **Group:** 13. Sites · **Was:** U99

## Why

Putting a built site on the web without other tools.

## What

A publish target set in Settings: where a built site (FF-120) is uploaded, with "Publish" and "Unpublish" on the site's page. First an S3 bucket with an AWS profile from `~/.aws`; Cloudflare R2 is the same code with its own endpoint, since it speaks S3's API; Cloudflare Pages needs its own upload route and is a further step.

## Acceptance criteria

Written when the task is planned into a group.

## Notes

- Until then a site is a folder in `Sites/`, uploaded with any tool (`aws s3 sync`, wrangler, a drag and drop).
- Targets are per computer (D52): a bucket, region or endpoint, a prefix and the profile to use; FilmFile keeps no keys. Where they're kept is decided when this is built.
- Publishing sends only what `site.json` says changed (FF-120's content-hashed names), removes files no longer in the site, sets content types, and gives the hashed images long caches and the page a short one.
- "Unpublish" removes everything under the site's prefix, after asking; the site's page shows whether it's published, and when.
- Whether to use the AWS SDK or sign requests ourselves is to decide when this is built (a new dependency needs a reason).
- Not in this task: setting up the bucket, CloudFront or Cloudflare.
