# FF-194 The app's version

**Status:** to do · **Group:** 10. Desktop app

## Why

Knowing which FilmFile I'm running, so I can tell whether a release has what I need and say which one has a problem, and never mistake a build from source for a release.

## What

FilmFile gets a real version number, kept only in the root `package.json` and starting at `0.1.0`. It's shown in the app's "About FilmFile" and at the foot of Settings, in the app and in a browser. Run from source, it's marked "(dev)". The API gives it on `GET /api/health`, and the disk image `pnpm package` makes carries it in its name. The Release workflow (FF-195) is what changes it.

## Acceptance criteria

- [ ] The root `package.json` is at version `0.1.0`. No other `package.json` holds FilmFile's version (`apps/desktop`, `apps/backend`, `apps/web` and `packages/contracts` stay at `0.0.0`).
- [ ] At the foot of Settings, below its forms, a quiet line reads "FilmFile 0.1.0", in the app and in a browser. Run from source (`pnpm start`, `pnpm dev`, `pnpm desktop`), it reads "FilmFile 0.1.0 (dev)".
- [ ] `GET /api/health` gives `version` ("0.1.0") and `dev` (`true` from source, `false` in a packaged app), and both are in the OpenAPI spec.
- [ ] On a Mac, the app menu's "About FilmFile" shows "FilmFile" and "Version 0.1.0" ("Version 0.1.0 (dev)" from source), and nothing else.
- [ ] On Windows and Linux, a Help menu has "About FilmFile". It opens a message box showing "FilmFile" and "Version 0.1.0" (with "(dev)" from source), with an "OK" button.
- [ ] A packaged app, from `pnpm package` or a release, shows the version it was built with, unmarked, however the service inside it is started.
- [ ] `pnpm package` names its disk image `FilmFile-0.1.0-mac-arm64.dmg`. The app folder keeps the packager's name (`FilmFile-darwin-arm64/`), so `install-app` and the packaged-app journey don't change. CI uploads the new name.

## Not in this task

- Changing the version, the changelog and releases (FF-195). The first release is `0.1.0` as this task sets it.
- Telling you a newer version is out (FF-138), or a "What's new" link.
- The commit a build was made from.
- A credits line or link in About.

## Notes

- One source: the root `package.json` (D109). The service reads it when run from source. When `package.ts` bundles the service, rolldown replaces a constant with the version, so the packaged service knows it however it's started. `package.ts` also writes it into the app's `package.json`. `dev` is `true` only when the version came from reading `package.json` at run time.
- From source, Electron's own version would be `apps/desktop`'s `0.0.0`, so the Mac's About panel is set with `app.setAboutPanelOptions` from the same version the service reports. The message box is Electron's `dialog.showMessageBox`.
- Health: `{ status: 'ok', exportToFolder, version: string, dev: boolean }`. Run `pnpm generate`.
- Tests:
  - Unit: reading the version, and the About text (with and without "(dev)").
  - API: health's `version` and `dev`.
  - Web: Settings shows "FilmFile 0.1.0 (dev)" from a fake health.
  - Packaged-app journey: health gives the version the app was built with, and `dev` is `false`.
  - `desktop.e2e.ts`: the menu has "About FilmFile".
  - Electron's native panel and message box aren't opened in tests.
