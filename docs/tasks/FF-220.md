# FF-220 The version shown for a frame in one place

**Status:** to do · **Group:** 16. Internal improvements

## Why

Which version stands for a frame (the one chosen, or else the first) is a rule (D15, D46), and the backend writes it twice: once in quick exports and once, as a private `shown` function, in site builds.

## What

One domain function, `shownVersion(frame)`, beside `find-version.ts`, and both use cases call it. Nothing changes in behaviour. _(Recommendation R9b of the architecture review.)_

## Acceptance criteria

- [ ] `apps/backend/src/domain/rolls/shown-version.ts` exports `shownVersion(frame: Frame): Version | undefined`: the version whose ID is the frame's `defaultVersion`, or else its first, or none when it has no versions. Its TSDoc cites D15 and D46.
- [ ] Unit tests in `shown-version.test.ts`: a chosen version, none chosen (the first), a chosen version that's no longer there (the first), and no versions.
- [ ] `make-quick-export.ts` and `build-site.ts` call it; `build-site.ts`'s private `shown` is gone.
- [ ] All tests pass unchanged.

## Not in this task

- The web app's own `apps/web/src/rolls/shown-version.ts`: the web may only import contracts, so it keeps its copy.
